투자 브리핑 Spring Boot 백엔드 설계
PART 01. 프로젝트 기준 및 DB 약칭 명명 규칙
============================================================

문서 목적
------------------------------------------------------------
이 문서는 투자 브리핑 백엔드 개발을 순서대로 진행하기 위한 첫 번째 설계 문서다.

이번 문서에서는 다음 항목을 확정한다.

1. 프로젝트 개발 기준
2. 데이터베이스 명명 규칙
3. 테이블명 약칭 규칙
4. 컬럼명 약칭 규칙
5. 전체 테이블 목록
6. 공통 컬럼 정의
7. 코드값과 Enum 관리 기준
8. 이후 문서 작성 순서

※ 계산식은 기존에 작성한 내용을 유지한다.
※ 이번 문서에서는 계산식 자체를 변경하지 않는다.
※ 테이블 및 컬럼 이름만 짧고 일관된 약칭으로 확정한다.
※ 테이블과 컬럼에는 PostgreSQL COMMENT를 반드시 작성한다.


============================================================
1. 프로젝트 기본 기준
============================================================

프로젝트명
- 투자 브리핑 시스템
- 영문명: Investment Briefing System

기본 패키지
- com.nanum.investment

개발 환경
- Java 21
- Spring Boot 3.5.7
- Gradle Groovy
- PostgreSQL
- Spring Data JPA
- QueryDSL
- MapStruct
- Lombok
- OpenAI API
- Scheduler

계좌 구분
- 국내계좌
- 해외계좌
- ISA계좌
- 연금계좌

# 주석
# 국내계좌와 해외계좌는 기존 종합계좌를 분리한 별도 계좌다.
# 모든 계산, 현금관리, 목표비중, 정기매수, 추가매수는 계좌별로 분리한다.
# 한 계좌의 현금을 다른 계좌의 매수 가능 현금으로 자동 합산하지 않는다.

2. 데이터베이스 명명 기본 규칙
============================================================

2.1 기본 형식

테이블명
- TB_약칭

예시
- TB_ACCT
- TB_STK
- TB_HOLD
- TB_INV_DEC

컬럼명
- 대문자 영문 약칭
- 단어 사이에는 밑줄 사용

예시
- ACCT_ID
- STK_CD
- TGT_WGT
- BUY_AMT

Primary Key
- 테이블의 대표 약칭 + _ID

예시
- ACCT_ID
- HOLD_ID
- INV_DEC_ID
- BRF_ID

Foreign Key
- 참조 대상 테이블의 PK명과 동일하게 사용

예시
- TB_HOLD.ACCT_ID
- TB_HOLD.STK_ID
- TB_STK_DEC.INV_DEC_ID


2.2 이름 길이 기준

- 테이블명은 가능하면 20자 이내로 작성한다.
- 컬럼명은 가능하면 30자 이내로 작성한다.
- 의미를 알 수 없을 정도로 과도하게 줄이지 않는다.
- 동일한 단어는 모든 테이블에서 같은 약칭을 사용한다.

좋은 예
- ACCOUNT → ACCT
- INVESTMENT → INV
- DECISION → DEC
- BRIEFING → BRF
- REBALANCE → REBAL
- RESERVE → RSV

나쁜 예
- ACCOUNT를 어떤 곳에서는 ACC, 다른 곳에서는 ACCT로 사용
- INVESTMENT를 INV, IVT, INVT로 혼용
- CURRENT를 CUR, CRT로 혼용


2.3 날짜와 시간 기준

날짜
- *_DT

예시
- BASE_DT
- TRADE_DT
- DEC_DT

일시
- *_DTTM

예시
- CRT_DTTM
- UPD_DTTM
- GEN_DTTM

시작일
- STRT_DT

종료일
- END_DT

# 주석
# PostgreSQL 타입은 날짜만 필요하면 DATE를 사용한다.
# 시간까지 필요하면 TIMESTAMP WITH TIME ZONE 사용을 우선 검토한다.
# 운영 시간대는 Asia/Seoul을 기준으로 한다.


2.4 금액과 가격 기준

금액
- *_AMT

예시
- EVL_AMT
- BUY_AMT
- CASH_AMT

가격
- *_PRC

예시
- AVG_PRC
- CUR_PRC
- CLS_PRC

수량
- *_QTY

예시
- HOLD_QTY
- BUY_QTY

# 주석
# 원화 금액은 BIGINT 또는 NUMERIC을 사용한다.
# 해외주식 가격, 환율, 수량은 소수점이 필요하므로 NUMERIC을 사용한다.
# Java에서는 정밀도가 필요한 금액과 비율에 BigDecimal 사용을 권장한다.


2.5 비율과 점수 기준

비율
- *_RT

예시
- PL_RT
- DD_RT
- CASH_RT

비중
- *_WGT

예시
- TGT_WGT
- CUR_WGT

점수
- *_SCR

예시
- MKT_SCR
- SENT_SCR
- RISK_SCR

배수
- *_MULT

예시
- BUY_MULT
- MAX_MULT

# 주석
# 비율 저장 방식은 0~100 기준으로 통일한다.
# 예: 12.5%는 12.5로 저장한다.
# 비중도 0~100 기준으로 통일하는 것을 권장한다.
# Java 계산식과 DB 저장 단위를 반드시 동일하게 유지한다.


2.6 상태와 유형 기준

상태
- *_STS

예시
- PROC_STS
- WGT_STS
- BUY_STS

유형
- *_TP

예시
- ACCT_TP
- BRF_TP
- MKT_TP

구분 코드
- *_CD

예시
- STK_CD
- MKT_CD
- BASE_IDX_CD

사용 여부
- USE_YN

삭제 여부
- DEL_YN

실행 여부
- EXEC_YN

# 주석
# Y/N 컬럼은 CHAR(1)을 사용하고 CHECK 제약조건을 적용한다.
# 상태값은 Enum과 DB 문자열 값을 동일하게 맞춘다.

4. 전체 테이블 목록
============================================================

4.1 기준정보 테이블

1) TB_ACCT
- 정식명: Account
- 한글명: 계좌 정보
- 설명: 국내, 해외, ISA, 연금 계좌의 기본정보와 현금정보를 관리한다.

2) TB_STK
- 정식명: Stock
- 한글명: 종목 정보
- 설명: 국내주식, 해외주식, ETF 등의 종목 기준정보를 관리한다.

3) TB_IDX
- 정식명: Market Index
- 한글명: 기준지수 정보
- 설명: 코스피, 코스닥, S&P500, 나스닥100, SMH 등 기준지수를 관리한다.

4) TB_INV_RULE
- 정식명: Investment Rule
- 한글명: 투자 규칙
- 설명: 시장국면, 매수배수, 비중초과 기준 등 계산 규칙을 관리한다.

5) TB_CD_GRP
- 정식명: Code Group
- 한글명: 공통코드 그룹
- 설명: 공통코드의 그룹 정보를 관리한다.

6) TB_CD_DTL
- 정식명: Code Detail
- 한글명: 공통코드 상세
- 설명: 계좌유형, 행동신호, 시장국면 등 공통코드 값을 관리한다.


4.2 계좌 및 보유정보 테이블

7) TB_HOLD
- 정식명: Holding
- 한글명: 보유종목
- 설명: 계좌별 종목 수량, 평단가, 현재가, 평가금액, 손익을 관리한다.

8) TB_REG_BUY
- 정식명: Regular Buy Setting
- 한글명: 정기매수 설정
- 설명: 종목별 최소금액, 최대금액, 주기, 활성 상태를 관리한다.

9) TB_CASH_RSV
- 정식명: Cash Reserve
- 한글명: 추가매수 대기현금
- 설명: 정기매수 감액 및 중단으로 확보한 계좌별 현금을 관리한다.

10) TB_CASH_HIS
- 정식명: Cash History
- 한글명: 현금 증감 이력
- 설명: 현금 적립, 사용, 입금, 출금 이력을 관리한다.


4.3 시장 데이터 테이블

11) TB_MKT_SNAP
- 정식명: Market Snapshot
- 한글명: 시장 스냅샷
- 설명: 기준일의 시장지수, 수급, 환율, 금리, 변동성 등을 저장한다.

12) TB_MKT_SENT
- 정식명: Market Sentiment
- 한글명: 시장심리 분석
- 설명: 뉴스 공포, AI 투자 피로, 실적 신뢰도, 심리단계를 저장한다.

13) TB_PRC_DAY
- 정식명: Daily Price
- 한글명: 일별 종목시세
- 설명: 종목별 일별 시가, 고가, 저가, 종가, 거래량을 저장한다.

14) TB_IDX_DAY
- 정식명: Daily Index
- 한글명: 일별 지수시세
- 설명: 기준지수별 일별 지수값과 등락률을 저장한다.

15) TB_EXCH_DAY
- 정식명: Daily Exchange Rate
- 한글명: 일별 환율
- 설명: 원/달러 등 주요 환율 데이터를 저장한다.

16) TB_BOND_DAY
- 정식명: Daily Bond Yield
- 한글명: 일별 채권금리
- 설명: 미국 10년물 등 주요 채권금리를 저장한다.


4.4 투자판단 테이블

17) TB_INV_DEC
- 정식명: Investment Decision
- 한글명: 투자판단
- 설명: 기준일의 시장국면, 시장점수, 종합판단 결과를 저장한다.

18) TB_STK_DEC
- 정식명: Stock Decision
- 한글명: 종목별 투자판단
- 설명: 종목별 행동신호, 매수배수, 추천금액, 판단근거를 저장한다.

19) TB_DEC_CHG
- 정식명: Decision Change History
- 한글명: 판단 변경이력
- 설명: 전일 대비 행동신호, 배수, 금액 변경내용을 저장한다.

20) TB_ADD_BUY
- 정식명: Additional Buy Plan
- 한글명: 추가매수 계획
- 설명: 추가매수 후보, 우선순위, 추천금액을 저장한다.

21) TB_REBUY
- 정식명: Rebuy Plan
- 한글명: 재매수 계획
- 설명: 과거 중단 또는 매도 종목의 재매수 조건과 판단결과를 저장한다.


4.5 리밸런싱 테이블

22) TB_REBAL
- 정식명: Rebalance Plan
- 한글명: 리밸런싱 계획
- 설명: 주간 또는 월간 리밸런싱의 기본정보를 저장한다.

23) TB_REBAL_ITEM
- 정식명: Rebalance Item
- 한글명: 리밸런싱 항목
- 설명: 종목별 변경 전후 비중, 금액, 행동계획을 저장한다.


4.6 브리핑 및 운영 테이블

24) TB_BRF
- 정식명: Briefing
- 한글명: 투자 브리핑
- 설명: 일일, 주간, 월간 브리핑의 제목, 본문, 상태를 저장한다.

25) TB_BRF_ITEM
- 정식명: Briefing Item
- 한글명: 브리핑 항목
- 설명: 브리핑의 시장, 종목, 위험, 행동계획 등 세부 항목을 저장한다.

26) TB_API_LOG
- 정식명: External API Log
- 한글명: 외부 API 호출이력
- 설명: KRX, Yahoo, 환율, OpenAI 등의 호출 결과를 저장한다.

27) TB_SCH_LOG
- 정식명: Scheduler Log
- 한글명: 스케줄러 실행이력
- 설명: 데이터수집, 계산, 브리핑 생성 작업의 실행결과를 저장한다.

28) TB_ERR_LOG
- 정식명: Error Log
- 한글명: 오류 로그
- 설명: 시스템 오류와 예외 정보를 저장한다.

5. 공통 컬럼 정의
============================================================

다음 컬럼은 필요한 테이블에 공통으로 적용한다.


5.1 생성 및 수정 정보

CRT_DTTM
- 한글명: 생성일시
- PostgreSQL 타입: TIMESTAMP WITH TIME ZONE
- 설명: 레코드가 최초 생성된 일시
- 기본값: CURRENT_TIMESTAMP

CRT_USR_ID
- 한글명: 생성자 ID
- PostgreSQL 타입: VARCHAR(50)
- 설명: 레코드를 생성한 사용자 또는 시스템 ID

UPD_DTTM
- 한글명: 수정일시
- PostgreSQL 타입: TIMESTAMP WITH TIME ZONE
- 설명: 레코드가 마지막으로 수정된 일시
- 기본값: CURRENT_TIMESTAMP

UPD_USR_ID
- 한글명: 수정자 ID
- PostgreSQL 타입: VARCHAR(50)
- 설명: 레코드를 마지막으로 수정한 사용자 또는 시스템 ID


5.2 사용 및 삭제 상태

USE_YN
- 한글명: 사용 여부
- PostgreSQL 타입: CHAR(1)
- 설명: 데이터 사용 여부
- 값: Y 또는 N
- 기본값: Y

DEL_YN
- 한글명: 삭제 여부
- PostgreSQL 타입: CHAR(1)
- 설명: 논리 삭제 여부
- 값: Y 또는 N
- 기본값: N

# 주석
# 기준정보와 설정정보에는 USE_YN을 사용한다.
# 이력성 데이터는 불필요한 경우 USE_YN을 생략할 수 있다.
# 투자판단과 시세 이력은 원칙적으로 물리 삭제하지 않는다.


5.3 정렬 및 버전

SORT_SEQ
- 한글명: 정렬 순번
- PostgreSQL 타입: INTEGER
- 설명: 화면 및 처리 순서를 위한 정렬값

VER_NO
- 한글명: 버전 번호
- PostgreSQL 타입: INTEGER
- 설명: 계산 규칙 또는 레코드의 버전

# 주석

7. PostgreSQL COMMENT 작성 규칙
============================================================

모든 테이블에는 COMMENT ON TABLE을 작성한다.

예시

COMMENT ON TABLE TB_ACCT IS '계좌 정보';


모든 컬럼에는 COMMENT ON COLUMN을 작성한다.

예시

COMMENT ON COLUMN TB_ACCT.ACCT_ID IS '계좌 ID';
COMMENT ON COLUMN TB_ACCT.ACCT_TP IS '계좌 유형';
COMMENT ON COLUMN TB_ACCT.ACCT_NM IS '계좌명';


코드 컬럼은 가능한 값을 주석에 포함한다.

예시

COMMENT ON COLUMN TB_ACCT.ACCT_TP
IS '계좌 유형(DOMESTIC:국내, OVERSEAS:해외, ISA:ISA, PENSION:연금)';


Y/N 컬럼도 값을 명확히 작성한다.

예시

COMMENT ON COLUMN TB_ACCT.USE_YN
IS '사용 여부(Y:사용, N:미사용)';

→ TbAddBuy

→ TbRebal

→ TbRebalItem

# 주석
# Entity 클래스에는 사용자 기존 규칙대로 Tb 접두사를 사용한다.
# DB 컬럼 약칭을 Java 필드명까지 그대로 축약할 필요는 없다.
# Java 필드는 읽기 쉽게 전체 단어를 사용한다.

예시

DB 컬럼
- ACCT_ID

Java 필드
- accountId

DB 컬럼
- TGT_WGT

Java 필드
- targetWeight

DB 컬럼
- REG_BUY_AMT

Java 필드
- regularBuyAmount


============================================================
9. 이번 문서에서 확정된 주요 사항
============================================================

1. 테이블명은 TB_약칭 형식으로 사용한다.
2. 계좌 테이블은 TB_ACCT로 사용한다.
3. 종목 테이블은 TB_STK로 사용한다.
4. 보유종목 테이블은 TB_HOLD로 사용한다.
5. 정기매수 설정은 TB_REG_BUY로 사용한다.
6. 투자판단은 TB_INV_DEC로 사용한다.
7. 종목별 판단은 TB_STK_DEC로 사용한다.
8. 브리핑은 TB_BRF로 사용한다.
9. 모든 테이블과 컬럼에 PostgreSQL COMMENT를 작성한다.
10. 비율과 비중은 0~100 단위로 저장한다.
11. 국내, 해외, ISA, 연금계좌는 별도 계좌로 관리한다.
12. Java Entity는 Tb 접두사를 사용한다.
13. Java 필드명은 축약하지 않고 읽기 쉬운 전체 단어를 사용한다.
14. 계산식은 기존 작성 내용을 유지하고 다음 단계에서 DB 구조에 연결한다.
