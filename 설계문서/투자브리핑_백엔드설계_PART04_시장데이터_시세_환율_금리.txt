투자 브리핑 Spring Boot 백엔드 설계
PART 04. 시장데이터·시세·환율·금리 상세설계
대상 테이블:
TB_MKT_SNAP, TB_MKT_SENT, TB_PRC_DAY,
TB_IDX_DAY, TB_EXCH_DAY, TB_BOND_DAY
============================================================

문서 목적
------------------------------------------------------------
이 문서는 투자 브리핑 시스템에서 사용하는 시장 데이터,
시장심리, 종목시세, 지수시세, 환율, 채권금리의 저장 구조를 설계한다.

대상 테이블
1. TB_MKT_SNAP : 일별 시장 스냅샷
2. TB_MKT_SENT : 일별 시장심리 분석
3. TB_PRC_DAY  : 종목별 일별 시세
4. TB_IDX_DAY  : 기준지수별 일별 시세
5. TB_EXCH_DAY : 일별 환율
6. TB_BOND_DAY : 일별 채권금리

이번 문서에서 연결하는 주요 데이터
- 코스피·코스닥 등락
- 외국인·기관·개인 수급
- 외국인 선물 수급
- 프로그램 매매
- 원/달러 환율
- 미국 채권금리
- 시장 변동성
- 상승·하락 종목 수
- 시장 확산도
- 종목 및 기준지수 고점 대비 하락률
- 뉴스 공포 점수
- AI 투자 피로 점수
- 실적 신뢰도
- 유동성 점수
- 시장심리 단계
- 구조적 훼손 가능성
- 데이터 신뢰도 및 최신성

※ 데이터 수집과 투자판단 계산은 분리한다.
※ 외부 API 실패 시 마지막 정상 데이터 사용 여부를 명확히 기록한다.
※ 모든 데이터에는 기준일, 수집일시, 출처, 최신성 상태를 저장한다.


============================================================
1. 시장 데이터 처리 원칙
============================================================

1.1 기준일
------------------------------------------------------------

BASE_DT
- 시장 데이터가 실제로 발생한 거래일
- 예: 2026-07-29

COLLECT_DTTM
- 시스템이 외부 데이터를 수집한 시각

# 주석
# BASE_DT와 COLLECT_DTTM은 다르다.
# 오전 브리핑에서는 전일 또는 최근 영업일 데이터를 사용할 수 있다.
# 휴일에는 마지막 거래일의 BASE_DT가 유지될 수 있다.


1.2 데이터 최신성
------------------------------------------------------------

데이터 최신성 상태 값

FRESH
- 정상 최신 데이터

STALE
- 오래된 데이터
- 마지막 정상 데이터를 재사용한 경우

MISSING
- 데이터 없음

PARTIAL
- 일부 항목만 수집됨

ERROR
- 수집 오류

저장 컬럼
- DATA_STS
- DATA_AGE_MIN
- LAST_OK_DTTM

# 주석
# 투자판단 서비스는 DATA_STS가 ERROR 또는 MISSING이면
# 해당 항목을 점수 계산에서 제외하거나 신뢰도를 낮춘다.
# STALE 데이터를 사용한 경우 브리핑에 기준일을 표시한다.


1.3 데이터 출처 우선순위
------------------------------------------------------------

국내 지수 및 수급
1. KRX
2. 증권사 API
3. 수동 입력

해외 종목 및 지수
1. 공식 거래소 또는 공식 데이터
2. Yahoo Finance
3. 수동 입력

환율
1. 한국은행 또는 공공기관
2. 금융 데이터 API
3. 수동 입력

채권금리
1. FRED 또는 미국 재무부
2. 금융 데이터 API
3. 수동 입력

# 주석
# DATA_SRC_CD에 출처를 저장한다.
# 동일 데이터가 여러 출처에 존재하면 우선순위를 설정파일로 관리한다.


1.4 결측값 처리
------------------------------------------------------------

필수 원칙
- 0과 NULL을 구분한다.
- 데이터가 없으면 0을 저장하지 않는다.
- 수급이 실제 0인 경우에만 0을 저장한다.
- 전일 값 사용 시 STALE 상태를 기록한다.

결측 처리 방식
- IGNORE: 계산에서 제외
- LAST_VALUE: 마지막 정상값 사용
- DEFAULT_VALUE: 설정 기본값 사용
- FAIL: 계산 중단

권장 적용
- 지수 종가: LAST_VALUE
- 환율: LAST_VALUE
- 채권금리: LAST_VALUE
- 수급 데이터: IGNORE
- 뉴스심리: IGNORE 또는 중립값
- 변동성: LAST_VALUE 또는 IGNORE

2.3 주요 계산식
------------------------------------------------------------

시장 확산도 예시

MKT_BREADTH_RT
= ADV_STK_CNT
  / NULLIF(ADV_STK_CNT + DECL_STK_CNT, 0)
  × 100

상승·하락 비율 예시

상승하락비
= ADV_STK_CNT / NULLIF(DECL_STK_CNT, 0)

# 주석
# 시장 확산도 계산 방식은 기존 Java 계산식과 동일하게 유지한다.
# 0으로 나누는 경우 NULL로 처리한다.

3. TB_MKT_SENT 일별 시장심리 분석
============================================================

3.1 테이블 목적
------------------------------------------------------------
TB_MKT_SENT는 뉴스, 수급, 실적, 유동성, 환율, 금리 등의 정보를
종합하여 산출한 시장심리 점수와 단계를 저장한다.

# 주석
# OpenAI가 점수를 계산하지 않는다.
# Java 계산엔진이 점수와 단계를 결정한다.
# OpenAI는 저장된 결과를 설명하는 역할만 담당한다.

4.3 주요 계산식
------------------------------------------------------------

등락률

CHG_RT
= ((CLS_PRC - PREV_CLS_PRC) / PREV_CLS_PRC) × 100

52주 고점 대비 하락률

DD_52W_RT
= ((CLS_PRC - HIGH_52W_PRC) / HIGH_52W_PRC) × 100

기준기간 고점 대비 하락률

DD_HIGH_RT
= ((CLS_PRC - ALL_HIGH_PRC) / ALL_HIGH_PRC) × 100

# 주석
# 하락률은 음수로 저장한다.
# 예: 고점 대비 30% 하락이면 -30.0000

14. 데이터 검증 규칙
============================================================

종목시세
- CLS_PRC는 0 이상
- HIGH_PRC >= LOW_PRC
- HIGH_PRC >= OPEN_PRC
- HIGH_PRC >= CLS_PRC
- LOW_PRC <= OPEN_PRC
- LOW_PRC <= CLS_PRC

환율
- EXCH_RT > 0
- 전일 대비 급격한 변동 시 경고
- 기준통화와 표시통화가 같으면 저장하지 않음

채권금리
- 비정상적인 음수 또는 급변 값은 경고
- 출처별 단위가 퍼센트인지 소수인지 확인

시장수급
- 단위를 원, 천원, 백만원 중 하나로 통일
- 권장 저장 단위: 원 또는 백만원
- 시스템 전체에서 단위가 섞이지 않도록 설정값으로 고정

# 주석
# 수급금액 단위는 반드시 한 번 확정해야 한다.
# 권장안은 원 단위 NUMERIC 저장이지만 값이 매우 크면 백만원 단위도 가능하다.
# 어떤 방식을 사용하든 컬럼 주석과 API 문서에 단위를 명시한다.
