투자 브리핑 Spring Boot 백엔드 설계
PART 05. 투자판단·종목판단·추가매수·재매수 상세설계
대상 테이블:
TB_INV_DEC, TB_STK_DEC, TB_DEC_CHG, TB_ADD_BUY, TB_REBUY
============================================================

문서 목적
------------------------------------------------------------
이 문서는 투자 브리핑 시스템의 핵심 계산결과를 저장하는
투자판단 관련 테이블을 상세 설계한다.

대상 테이블
1. TB_INV_DEC : 일별 종합 투자판단
2. TB_STK_DEC : 종목별 투자판단
3. TB_DEC_CHG : 판단 변경이력
4. TB_ADD_BUY : 추가매수 계획
5. TB_REBUY   : 재매수 계획

이번 문서에서 연결하는 기존 계산결과
- 시장점수
- 시장국면
- 시장심리
- 시장 위험도
- 계좌 현금비중
- 종목별 현재비중
- 종목별 목표비중
- 비중상태
- 종목 위험등급
- 정기매수 배수
- 추천 정기매수금액
- 추가매수 우선순위
- 추가매수 추천금액
- 재매수 조건
- 행동신호
- 실행 여부
- 판단 신뢰도
- 이전 판단과 현재 판단 비교
- 변경 사유

※ 계산은 Java 서비스에서 수행한다.
※ OpenAI는 저장된 판단결과를 설명하는 역할만 담당한다.
※ 같은 기준일에 동일 계산을 재실행해도 중복 데이터가 생성되지 않아야 한다.
※ 모든 판단결과에는 계산규칙 버전과 입력 데이터 상태를 저장한다.


============================================================
1. 투자판단 저장 구조 개요
============================================================

1.1 처리 단위
------------------------------------------------------------

TB_INV_DEC
- 기준일별 종합 판단
- 시장 단위 또는 계좌 단위
- 한 번의 계산 실행을 대표하는 상위 레코드

TB_STK_DEC
- TB_INV_DEC에 포함되는 종목별 판단
- 보유종목 또는 관찰종목 단위

TB_DEC_CHG
- 전일 또는 직전 계산결과와 비교한 변경이력

TB_ADD_BUY
- 추가매수가 가능한 후보와 금액

TB_REBUY
- 매수중단 또는 매도 이후 재매수 후보와 조건


1.2 권장 관계
------------------------------------------------------------

TB_INV_DEC 1 : N TB_STK_DEC

TB_STK_DEC 1 : N TB_DEC_CHG

TB_STK_DEC 1 : 0..1 TB_ADD_BUY

TB_STK_DEC 1 : 0..1 TB_REBUY

# 주석
# 추가매수와 재매수는 종목판단에서 파생되는 별도 실행계획이다.
# 한 종목에 추가매수와 재매수가 동시에 생성되지 않도록 서비스에서 검증한다.


1.3 기준일과 실행번호
------------------------------------------------------------

BASE_DT
- 실제 판단 대상 거래일

CALC_SEQ
- 같은 기준일에 재계산된 순번
- 1, 2, 3...

LATEST_YN
- 같은 기준일의 최신 계산 여부

# 주석
# 재계산 시 기존 레코드를 덮어쓰기보다 새 계산순번을 생성하는 방식을 권장한다.
# 최신 결과만 조회할 때 LATEST_YN = 'Y' 조건을 사용한다.


============================================================
2. TB_INV_DEC 일별 종합 투자판단
============================================================

2.1 테이블 목적
------------------------------------------------------------
TB_INV_DEC는 기준일별 시장국면, 시장심리, 위험도,
계좌별 현금상태, 종합 행동방향을 저장한다.

저장 단위
- 시장 전체 판단
- 또는 계좌별 판단

권장안
- ACCT_ID가 NULL이면 시장 전체 판단
- ACCT_ID가 존재하면 계좌별 판단

# 주석
# 시장 전체 판단과 계좌별 판단을 한 테이블에서 관리한다.
# 계좌별 현금비중과 투자여력은 ACCT_ID가 있는 레코드에 저장한다.

2.3 주요 계산식 연결
------------------------------------------------------------

시장점수
- 시장 데이터 입력값을 가중합하여 Java에서 계산
- TB_INV_DEC.MKT_SCR 저장

시장국면
- 시장점수 구간과 구조적 위험조건으로 결정
- TB_INV_DEC.MKT_REGIME 저장

계좌 총자산

TOT_AST_AMT
= CASH_AMT
+ RSV_CASH_AMT
+ 계좌 내 보유종목 평가금액 합계

전체 현금비중

CASH_RT
= ((CASH_AMT + RSV_CASH_AMT) / TOT_AST_AMT) × 100

추천 정기매수 총액
- TB_STK_DEC.REG_BUY_AMT 합계

추천 추가매수 총액
- TB_ADD_BUY.RCMD_ADD_AMT 합계

대기현금 확보액
- TB_STK_DEC.SAVED_AMT 합계

        RISK_GRADE IN ('LOW', 'MEDIUM', 'HIGH', 'CRITICAL')
    ),
    CONSTRAINT CK_TB_INV_DEC_05 CHECK (
        CASH_RT IS NULL OR CASH_RT BETWEEN 0 AND 100
    ),
    CONSTRAINT CK_TB_INV_DEC_06 CHECK (
        TGT_CASH_RT IS NULL OR TGT_CASH_RT BETWEEN 0 AND 100
    ),
    CONSTRAINT CK_TB_INV_DEC_07 CHECK (
        OVR_DEC_SIG IN (
            'HOLD_CASH',
            'KEEP_REGULAR_BUY',
            'REDUCE_REGULAR_BUY',
            'INCREASE_REGULAR_BUY',
            'SELECTIVE_ADD_BUY',

CREATE INDEX IDX_TB_INV_DEC_01

============================================================
3. TB_STK_DEC 종목별 투자판단
============================================================

3.1 테이블 목적
------------------------------------------------------------
TB_STK_DEC는 특정 투자판단 실행에서 종목별로 계산된
현재비중, 목표비중, 위험도, 행동신호, 매수배수,
추천매수금액, 실행 여부를 저장한다.

# 주석
# 보유종목뿐 아니라 관찰종목도 포함할 수 있다.
# HOLD_ID는 보유종목인 경우에만 저장하고, 관찰종목이면 NULL을 허용한다.

------------------------------------------------------------

필수 조건 예시
- 펀더멘털 훼손 없음
- 종목등급이 핵심 또는 우량 위성
- 현재비중이 목표비중보다 낮음
- 종목 하락률이 설정 기준 이하
- 시장국면이 추가매수를 허용
- 계좌 대기현금이 충분함
- 사용자 중단 상태가 아님

추천금액 제한
- 종목별 최대 추가매수금액
- 계좌별 추가매수 예산
- 추가매수 대기현금 잔액
- 목표비중 부족액

6.1 테이블 목적
------------------------------------------------------------
TB_REBUY는 과거에 정기매수를 중단했거나 매도한 종목이
다시 매수 가능한 상태인지 판단한 결과를 저장한다.


6.2 재매수 조건 예시
------------------------------------------------------------

필수 조건
- 펀더멘털 훼손 없음
- 시장 구조적 위험 완화
- 종목 가격 안정
- 기준지수 대비 상대성과 개선
- 비중 부족
- 사용자 중단 해제 가능
- 현금 여력 존재

확인 신호 예시
- 20일 이동평균 회복
- 거래량 안정
- 급락 후 저점 재이탈 없음
- 기준지수 하락률 개선
- 외국인 또는 기관 수급 반전

11. 판단 변경이력 생성 기준
============================================================

신규 판단
- 직전 데이터 없음
- CHG_TP = NEW

행동신호 변경
- 이전 ACT_SIG != 현재 ACT_SIG
- CHG_TP = SIGNAL_CHANGE

추천금액 변경
- 이전 금액과 현재 금액 차이가 설정 임계값 이상
- CHG_TP = AMOUNT_CHANGE

매수배수 변경
- 이전 FINAL_MULT != 현재 FINAL_MULT
- CHG_TP = MULTIPLIER_CHANGE

위험등급 변경
- 이전 RISK_GRADE != 현재 RISK_GRADE
- CHG_TP = RISK_CHANGE

비중상태 변경
- 이전 WGT_STS != 현재 WGT_STS
- CHG_TP = WEIGHT_CHANGE

# 주석
# 하나의 종목판단에서 여러 변경이 발생하면
# 변경유형별로 여러 건을 저장하거나 대표 변경 한 건만 저장할 수 있다.
# 권장안은 변경유형별 다건 저장이다.

16. 데이터 검증 규칙
============================================================

TB_INV_DEC
- CONF_RT는 0~100
- 추천 총액은 매수 가능금액 이하
- 최신 판단은 기준일·계좌·시장코드별 1건

TB_STK_DEC
- FINAL_MULT는 0 이상
- 추천매수금액은 0 이상
- 실행금액은 추천금액을 초과하지 않도록 서비스 검증
- 목표비중과 현재비중은 0~100

TB_ADD_BUY
- ELIG_YN = N이면 추천금액은 0 또는 NULL
- 실행금액은 대기현금 이하
- 목표비중 부족금액 이하

TB_REBUY
- REBUY_SIG = BLOCKED이면 실행 불가
- REBUY_SIG = REBUY 또는 PARTIAL_REBUY일 때만 실행 가능
