투자 브리핑 Spring Boot 백엔드 설계
PART 11. 전체 REST API·OpenAPI·프론트엔드 화면연결 상세설계
============================================================

문서 목적
------------------------------------------------------------
이 문서는 PART 01~10에서 설계한 모든 도메인을
REST API, OpenAPI 문서, 프론트엔드 화면과 연결한다.

주요 대상
1. 계좌관리 API
2. 종목관리 API
3. 보유종목 API
4. 정기매수 API
5. 현금관리 API
6. 시장데이터 API
7. 투자판단 API
8. 추가매수·재매수 API
9. 리밸런싱 API
10. 브리핑 API
11. 관리자 로그 API
12. OpenAPI 문서
13. 프론트엔드 목록·상세 화면
14. 검색·필터·페이징
15. 상태변경 API
16. 실행등록 API
17. 권한과 보안
18. E2E 테스트

기술 기준
- Java 21
- Spring Boot 3.5.7
- Spring MVC
- Bean Validation
- Spring Data JPA
- QueryDSL
- springdoc-openapi
- PostgreSQL
- REST JSON API

※ Entity는 API에 직접 노출하지 않는다.
※ 모든 응답은 공통 ApiResponse로 감싼다.
※ 목록 API는 PageResponse를 사용한다.
※ 검색 조건은 QueryDSL로 처리한다.
※ 상태 변경은 일반 수정 API와 분리한다.
※ 실행 등록 API는 멱등성과 감사이력을 고려한다.


============================================================
1. 공통 API 규칙
============================================================

1.1 기본 URL
------------------------------------------------------------

/api

관리자 API
/api/admin

권장 버전 경로
/api/v1

초기에는 /api 사용 가능하나,
운영 확장성을 고려하면 /api/v1 권장


1.2 HTTP Method
------------------------------------------------------------

GET
- 조회

POST
- 생성
- 계산 실행
- 상태전이
- 승인·발행·실행등록

PUT
- 전체 수정

PATCH
- 일부 수정

DELETE
- 논리삭제


1.3 공통 응답
------------------------------------------------------------

성공

{
  "success": true,
  "data": {},
  "error": null,
  "timestamp": "2026-07-30T20:00:00+09:00",
  "traceId": "..."
}

실패

{
  "success": false,
  "data": null,
  "error": {
    "code": "ACCOUNT-404-001",
    "message": "계좌를 찾을 수 없습니다.",
    "validationErrors": []
  },
  "timestamp": "2026-07-30T20:00:00+09:00",
  "traceId": "..."
}


1.4 페이징
------------------------------------------------------------

요청
- page
- size
- sort

기본값
- page = 0
- size = 20
- 최대 size = 200

응답
- content
- page
- size
- totalElements
- totalPages
- first
- last


1.5 정렬
------------------------------------------------------------

예시

?sort=baseDate,desc
?sort=stockName,asc

허용된 정렬필드만 사용
- 임의 컬럼명 차단
- SQL Injection 방지


1.6 검색 날짜
------------------------------------------------------------

ISO-8601 사용

예시
- 2026-07-30

기간조건
- fromDate
- toDate


1.7 멱등성
------------------------------------------------------------

권장 요청 헤더
- Idempotency-Key

적용 대상
- 리밸런싱 실행

21. Controller 공통 예시
============================================================

@RestController
@RequestMapping("/api/v1/holdings")
@RequiredArgsConstructor
@Tag(name = "Holdings")
public class HoldingController {

    private final HoldingService holdingService;

    @GetMapping
    @Operation(summary = "보유종목 목록 조회")
    public ApiResponse<PageResponse<HoldingResponse>> search(
        @Valid HoldingSearchCondition condition,
        @PageableDefault(size = 20) Pageable pageable,
        HttpServletRequest request
    ) {
        return ApiResponse.success(
            holdingService.search(condition, pageable),
            TraceIdUtils.resolve(request)
        );
    }

    @GetMapping("/{holdingId}")
    @Operation(summary = "보유종목 상세 조회")
    public ApiResponse<HoldingResponse> get(
        @PathVariable Long holdingId,
        HttpServletRequest request
    ) {
        return ApiResponse.success(
            holdingService.get(holdingId),
            TraceIdUtils.resolve(request)
        );
    }
}
