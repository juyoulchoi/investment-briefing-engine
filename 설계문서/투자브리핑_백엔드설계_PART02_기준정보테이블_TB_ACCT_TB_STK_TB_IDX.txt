투자 브리핑 Spring Boot 백엔드 설계
PART 02. 기준정보 테이블 상세설계
대상 테이블: TB_ACCT, TB_STK, TB_IDX
============================================================

문서 목적
------------------------------------------------------------
이 문서는 투자 브리핑 시스템의 기준정보 테이블 3개를 상세 설계한다.

대상 테이블
1. TB_ACCT : 계좌 정보
2. TB_STK  : 종목 정보
3. TB_IDX  : 기준지수 정보

각 테이블마다 다음 내용을 포함한다.
- 테이블 목적
- 컬럼 정의
- 데이터 타입과 NULL 허용 여부
- 기본값
- PK, FK, UNIQUE, CHECK
- 인덱스
- PostgreSQL CREATE TABLE
- COMMENT ON TABLE / COLUMN
- 샘플 데이터
- Java Entity, Repository, DTO 예시
- Validation과 구현 주의사항


============================================================
1. TB_IDX 기준지수 정보
============================================================

1.1 테이블 목적
------------------------------------------------------------
TB_IDX는 종목의 시장 하락률과 상대성과를 판단하기 위한 기준지수를 관리한다.

예시
- KOSPI
- KOSDAQ
- KOSPI200
- S&P500
- NASDAQ100
- SMH
- 미국 배당지수
- 채권지수
- 원자재지수

# 주석
# TB_STK.BASE_IDX_ID가 이 테이블의 IDX_ID를 참조한다.
# 종목별 시장하락률은 연결된 기준지수의 고점 대비 하락률을 사용한다.
# ETF를 기준지수 대용으로 사용할 수 있으므로 IDX_TP으로 유형을 구분한다.


1.2 컬럼 정의
------------------------------------------------------------

IDX_ID
- 한글명: 기준지수 ID
- 타입: BIGINT
- NULL: 불가
- 기본값: IDENTITY
- 키: PK

IDX_CD
- 한글명: 기준지수 코드
- 타입: VARCHAR(30)
- NULL: 불가
- 키: UNIQUE
- 예시: KOSPI, KOSPI200, SP500, NASDAQ100, SMH

IDX_NM
- 한글명: 기준지수명
- 타입: VARCHAR(150)
- NULL: 불가

IDX_NM_EN
- 한글명: 영문 기준지수명
- 타입: VARCHAR(200)
- NULL: 가능

IDX_TP
- 한글명: 기준지수 유형
- 타입: VARCHAR(30)
- NULL: 불가
- 값: MARKET, SECTOR, ETF_PROXY, BOND, COMMODITY

MKT_CD
- 한글명: 시장 코드
- 타입: VARCHAR(30)
- NULL: 가능

CNTRY_CD
- 한글명: 국가 코드
- 타입: VARCHAR(10)
- NULL: 불가

CURR_CD
- 한글명: 통화 코드
- 타입: VARCHAR(10)
- NULL: 불가

DATA_SRC_CD
- 한글명: 데이터 출처 코드
- 타입: VARCHAR(30)
- NULL: 불가
- 값: KRX, YAHOO, FRED, MANUAL

SRC_SYMBOL
- 한글명: 출처 심볼
- 타입: VARCHAR(50)
- NULL: 가능
- 예시: ^KS11, ^GSPC, ^NDX, SMH

DFLT_YN
- 한글명: 기본 기준지수 여부
- 타입: CHAR(1)
- NULL: 불가
- 기본값: N

USE_YN
- 한글명: 사용 여부
- 타입: CHAR(1)
- NULL: 불가
- 기본값: Y

DEL_YN
- 한글명: 삭제 여부
- 타입: CHAR(1)
- NULL: 불가
- 기본값: N

CRT_DTTM
- 한글명: 생성일시
- 타입: TIMESTAMP WITH TIME ZONE
- NULL: 불가
- 기본값: CURRENT_TIMESTAMP

CRT_USR_ID
- 한글명: 생성자 ID
- 타입: VARCHAR(50)
- NULL: 가능

UPD_DTTM
- 한글명: 수정일시
- 타입: TIMESTAMP WITH TIME ZONE
- NULL: 불가
- 기본값: CURRENT_TIMESTAMP

UPD_USR_ID
- 한글명: 수정자 ID
- 타입: VARCHAR(50)
- NULL: 가능


1.3 PostgreSQL DDL
------------------------------------------------------------

CREATE TABLE TB_IDX (
    IDX_ID          BIGINT GENERATED BY DEFAULT AS IDENTITY,
    IDX_CD          VARCHAR(30)             NOT NULL,
    IDX_NM          VARCHAR(150)            NOT NULL,
    IDX_NM_EN       VARCHAR(200),
    IDX_TP          VARCHAR(30)             NOT NULL,
    MKT_CD          VARCHAR(30),
    CNTRY_CD        VARCHAR(10)             NOT NULL,
    CURR_CD         VARCHAR(10)             NOT NULL,
    DATA_SRC_CD     VARCHAR(30)             NOT NULL,
    SRC_SYMBOL      VARCHAR(50),
    DFLT_YN         CHAR(1)                 NOT NULL DEFAULT 'N',
    USE_YN          CHAR(1)                 NOT NULL DEFAULT 'Y',
    DEL_YN          CHAR(1)                 NOT NULL DEFAULT 'N',
    CRT_DTTM        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CRT_USR_ID      VARCHAR(50),
    UPD_DTTM        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UPD_USR_ID      VARCHAR(50),

    CONSTRAINT PK_TB_IDX PRIMARY KEY (IDX_ID),
    CONSTRAINT UK_TB_IDX_01 UNIQUE (IDX_CD),
    CONSTRAINT CK_TB_IDX_01 CHECK (
        IDX_TP IN ('MARKET', 'SECTOR', 'ETF_PROXY', 'BOND', 'COMMODITY')
    ),
    CONSTRAINT CK_TB_IDX_02 CHECK (
        DATA_SRC_CD IN ('KRX', 'YAHOO', 'FRED', 'MANUAL')
    ),
    CONSTRAINT CK_TB_IDX_03 CHECK (DFLT_YN IN ('Y', 'N')),
    CONSTRAINT CK_TB_IDX_04 CHECK (USE_YN IN ('Y', 'N')),
    CONSTRAINT CK_TB_IDX_05 CHECK (DEL_YN IN ('Y', 'N'))
);

CREATE INDEX IDX_TB_IDX_01 ON TB_IDX (IDX_TP);
CREATE INDEX IDX_TB_IDX_02 ON TB_IDX (DATA_SRC_CD, SRC_SYMBOL);
CREATE INDEX IDX_TB_IDX_03 ON TB_IDX (USE_YN, DEL_YN);

1.6 Java Entity 예시
------------------------------------------------------------

@Entity
@Table(
    name = "TB_IDX",
    uniqueConstraints = {
        @UniqueConstraint(name = "UK_TB_IDX_01", columnNames = "IDX_CD")
    }
)
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class TbIdx {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "IDX_ID", nullable = false)
    private Long indexId;

    @Column(name = "IDX_CD", nullable = false, length = 30)
    private String indexCode;

    @Column(name = "IDX_NM", nullable = false, length = 150)
    private String indexName;

    @Column(name = "IDX_NM_EN", length = 200)
    private String indexEnglishName;

    @Enumerated(EnumType.STRING)
    @Column(name = "IDX_TP", nullable = false, length = 30)
    private IndexType indexType;

    @Column(name = "MKT_CD", length = 30)
    private String marketCode;

    @Column(name = "CNTRY_CD", nullable = false, length = 10)
    private String countryCode;

    @Column(name = "CURR_CD", nullable = false, length = 10)
    private String currencyCode;

    @Enumerated(EnumType.STRING)
    @Column(name = "DATA_SRC_CD", nullable = false, length = 30)
    private DataSourceCode dataSourceCode;

    @Column(name = "SRC_SYMBOL", length = 50)
    private String sourceSymbol;

    @Column(name = "DFLT_YN", nullable = false, length = 1)
    private String defaultYn;

    @Column(name = "USE_YN", nullable = false, length = 1)
    private String useYn;

    @Column(name = "DEL_YN", nullable = false, length = 1)
    private String deleteYn;

    @Column(name = "CRT_DTTM", nullable = false)
    private OffsetDateTime createdDateTime;

    @Column(name = "CRT_USR_ID", length = 50)
    private String createdUserId;

    @Column(name = "UPD_DTTM", nullable = false)
    private OffsetDateTime updatedDateTime;

    @Column(name = "UPD_USR_ID", length = 50)
    private String updatedUserId;
}

1.9 구현 주의사항
------------------------------------------------------------
- IDX_CD는 수정하지 않는 업무키로 사용한다.
- SRC_SYMBOL은 데이터 출처별로 다를 수 있다.
- 기준지수 삭제 전 TB_STK 참조 여부를 확인한다.
- 기본 기준지수는 국가 또는 시장별 하나만 허용하도록 확장할 수 있다.


============================================================
2. TB_ACCT 계좌 정보
============================================================

2.1 테이블 목적
------------------------------------------------------------
TB_ACCT는 국내, 해외, ISA, 연금계좌의 기준정보와 현금을 관리한다.

# 주석
# CASH_AMT는 일반 현금이다.
# RSV_CASH_AMT는 정기매수 감액 또는 중단으로 확보한 추가매수 전용 현금이다.
# 실제 계좌번호 전체는 저장하지 않고 마스킹 값만 저장한다.


2.2 컬럼 정의
------------------------------------------------------------

ACCT_ID
- 계좌 ID
- BIGINT
- PK
- IDENTITY

ACCT_CD
- 계좌 코드
- VARCHAR(30)
- NOT NULL
- UNIQUE
- 예시: DOMESTIC_MAIN, OVERSEAS_MAIN, ISA_MAIN, PENSION_MAIN

ACCT_NM
- 계좌명
- VARCHAR(100)
- NOT NULL

ACCT_TP
- 계좌 유형
- VARCHAR(20)
- NOT NULL
- 값: DOMESTIC, OVERSEAS, ISA, PENSION

BRKR_CD
- 증권사 코드
- VARCHAR(30)
- NULL 허용

BRKR_NM
- 증권사명
- VARCHAR(100)
- NULL 허용

ACCT_NO_MASK
- 마스킹 계좌번호
- VARCHAR(50)
- NULL 허용

BASE_CURR_CD
- 기준 통화 코드
- VARCHAR(10)
- NOT NULL
- 기본값: KRW

CASH_AMT
- 일반 현금
- NUMERIC(20,4)
- NOT NULL
- 기본값: 0

RSV_CASH_AMT
- 추가매수 대기현금
- NUMERIC(20,4)
- NOT NULL
- 기본값: 0

TGT_CASH_WGT
- 목표 현금비중
- NUMERIC(7,4)
- NULL 허용
- 저장단위: 0~100

DISP_SEQ
- 표시 순번
- INTEGER
- NOT NULL
- 기본값: 0

USE_YN
- 사용 여부
- CHAR(1)
- NOT NULL
- 기본값: Y

DEL_YN
- 삭제 여부
- CHAR(1)
- NOT NULL
- 기본값: N

CRT_DTTM
- 생성일시
- TIMESTAMP WITH TIME ZONE
- NOT NULL
- 기본값: CURRENT_TIMESTAMP

CRT_USR_ID
- 생성자 ID
- VARCHAR(50)
- NULL 허용

UPD_DTTM
- 수정일시
- TIMESTAMP WITH TIME ZONE
- NOT NULL
- 기본값: CURRENT_TIMESTAMP

UPD_USR_ID
- 수정자 ID
- VARCHAR(50)
- NULL 허용


2.3 PostgreSQL DDL
------------------------------------------------------------

CREATE TABLE TB_ACCT (
    ACCT_ID         BIGINT GENERATED BY DEFAULT AS IDENTITY,
    ACCT_CD         VARCHAR(30)             NOT NULL,
    ACCT_NM         VARCHAR(100)            NOT NULL,
    ACCT_TP         VARCHAR(20)             NOT NULL,
    BRKR_CD         VARCHAR(30),
    BRKR_NM         VARCHAR(100),
    ACCT_NO_MASK    VARCHAR(50),
    BASE_CURR_CD    VARCHAR(10)             NOT NULL DEFAULT 'KRW',
    CASH_AMT        NUMERIC(20,4)           NOT NULL DEFAULT 0,
    RSV_CASH_AMT    NUMERIC(20,4)           NOT NULL DEFAULT 0,
    TGT_CASH_WGT    NUMERIC(7,4),
    DISP_SEQ        INTEGER                 NOT NULL DEFAULT 0,
    USE_YN          CHAR(1)                 NOT NULL DEFAULT 'Y',
    DEL_YN          CHAR(1)                 NOT NULL DEFAULT 'N',
    CRT_DTTM        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CRT_USR_ID      VARCHAR(50),
    UPD_DTTM        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UPD_USR_ID      VARCHAR(50),

    CONSTRAINT PK_TB_ACCT PRIMARY KEY (ACCT_ID),
    CONSTRAINT UK_TB_ACCT_01 UNIQUE (ACCT_CD),
    CONSTRAINT CK_TB_ACCT_01 CHECK (
        ACCT_TP IN ('DOMESTIC', 'OVERSEAS', 'ISA', 'PENSION')
    ),
    CONSTRAINT CK_TB_ACCT_02 CHECK (
        BASE_CURR_CD IN ('KRW', 'USD')
    ),
    CONSTRAINT CK_TB_ACCT_03 CHECK (CASH_AMT >= 0),
    CONSTRAINT CK_TB_ACCT_04 CHECK (RSV_CASH_AMT >= 0),
    CONSTRAINT CK_TB_ACCT_05 CHECK (
        TGT_CASH_WGT IS NULL OR TGT_CASH_WGT BETWEEN 0 AND 100
    ),
    CONSTRAINT CK_TB_ACCT_06 CHECK (USE_YN IN ('Y', 'N')),
    CONSTRAINT CK_TB_ACCT_07 CHECK (DEL_YN IN ('Y', 'N'))
);

CREATE INDEX IDX_TB_ACCT_01 ON TB_ACCT (ACCT_TP);
CREATE INDEX IDX_TB_ACCT_02 ON TB_ACCT (USE_YN, DEL_YN);

2.6 Java Entity 예시

@Entity
@Table(
    name = "TB_ACCT",
    uniqueConstraints = {
        @UniqueConstraint(name = "UK_TB_ACCT_01", columnNames = "ACCT_CD")
    }
)
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class TbAcct {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "ACCT_ID", nullable = false)
    private Long accountId;

    @Column(name = "ACCT_CD", nullable = false, length = 30)
    private String accountCode;

    @Column(name = "ACCT_NM", nullable = false, length = 100)
    private String accountName;

    @Enumerated(EnumType.STRING)
    @Column(name = "ACCT_TP", nullable = false, length = 20)
    private AccountType accountType;

    @Column(name = "BRKR_CD", length = 30)
    private String brokerCode;

2.9 구현 주의사항
------------------------------------------------------------
- ACCT_CD는 수정하지 않는 업무키로 사용한다.
- 일반 현금과 대기현금의 중복 합산을 방지한다.
- 계좌 현금 변경은 트랜잭션으로 처리한다.
- 실제 계좌번호 원문은 저장하지 않는다.
- 삭제는 DEL_YN 기반 논리 삭제를 우선한다.

3.9 구현 주의사항
------------------------------------------------------------
- 국내 종목코드는 문자열로 저장한다.
- 해외 티커는 저장 전에 대문자로 정규화한다.
- 시장코드와 티커 조합은 중복되지 않아야 한다.
- 기준지수 미매핑 종목을 위해 BASE_IDX_ID는 NULL을 허용한다.
- 삭제된 종목도 과거 판단과 시세 이력 때문에 물리 삭제하지 않는다.
