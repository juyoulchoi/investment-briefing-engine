투자 브리핑 Spring Boot 백엔드 설계
PART 09. 투자판단 계산엔진 상세설계
============================================================

문서 목적
------------------------------------------------------------
이 문서는 투자 브리핑 시스템의 핵심 계산엔진을
Java 클래스와 메서드 단위로 상세 설계한다.

주요 대상
1. 시장점수 계산기
2. 시장국면 판정기
3. 시장심리 계산기
4. 계좌 총자산 계산기
5. 현금비중 계산기
6. 종목 비중 계산기
7. 정기매수 배수 계산기
8. 추천 정기매수금액 계산기
9. 정기매수 감액분 계산기
10. 추가매수 우선순위 계산기
11. 추가매수 추천금액 계산기
12. 재매수 조건 계산기
13. 종목 신호등 계산기
14. 종합 행동신호 계산기
15. 계산규칙 버전관리
16. 단위 테스트 시나리오

기술 기준
- Java 21
- Spring Boot 3.5.7
- BigDecimal 기반 계산
- 계산결과 불변 객체 사용
- 계산식과 데이터 조회 분리
- 계산규칙 버전관리
- 단위 테스트 우선

※ 계산기는 DB에 직접 접근하지 않는다.
※ Service가 입력값을 조립하고 계산기에 전달한다.
※ 계산결과 저장은 별도 Orchestrator 또는 Service가 담당한다.
※ 모든 비율은 퍼센트 단위로 통일한다.
※ 모든 금액은 원화 기준으로 계산한 뒤 필요 시 외화 원값을 별도 보관한다.

3.1 목적
------------------------------------------------------------
시장점수는 시장의 방향성, 수급, 변동성, 환율, 금리,
시장 확산도, 유동성을 종합한 0~100 점수다.

높을수록
- 시장환경 양호

낮을수록
- 시장 위험 증가
- 감액 또는 중단 필요

3.4 구성점수 예시
------------------------------------------------------------

지수 방향성 점수

- +3% 이상: 100
- +1% 이상: 80
- 0% 이상: 60
- -1% 이상: 40
- -3% 이상: 20
- -3% 미만: 0

수급 점수
- 외국인과 기관 순매수금액을 시장 거래대금 대비 비율로 정규화
- 외국인 가중치가 기관보다 높음

선물·프로그램 점수
- 외국인 선물 순매수와 프로그램 비차익 순매수 중심

시장 확산도 점수
- 70 이상: 100
- 60 이상: 80
- 50 이상: 60
- 40 이상: 40
- 30 이상: 20
- 30 미만: 0

변동성 점수
- 변동성지수가 낮을수록 높은 점수
- 급등 시 추가 감점

환율 압력 점수
- 원·달러 환율 상승률이 높을수록 감점
- 외국인 순매수와 동시에 나타나면 감점 완화 가능

금리 압력 점수
- 미국 2년물과 10년물 급등 시 감점

유동성 점수
- 거래대금, 신용잔고, 정책유동성 등을 별도 계산 후 입력

3.7 구현 핵심 예시
------------------------------------------------------------

@Component
public class DefaultMarketScoreCalculator
        implements MarketScoreCalculator {

    @Override
    public MarketScoreResult calculate(
        MarketScoreInput input,
        MarketRuleSet ruleSet
    ) {
        BigDecimal trendScore =
            calculateTrendScore(input, ruleSet);

        BigDecimal flowScore =
            calculateFlowScore(input, ruleSet);

        BigDecimal futuresProgramScore =
            calculateFuturesProgramScore(input, ruleSet);

        BigDecimal breadthScore =
            calculateBreadthScore(input, ruleSet);

        BigDecimal volatilityScore =
            calculateVolatilityScore(input, ruleSet);

        BigDecimal exchangeScore =
            calculateExchangeScore(input, ruleSet);

        BigDecimal rateScore =
            calculateRateScore(input, ruleSet);

        BigDecimal liquidityScore =
            defaultNeutral(input.liquidityScore());

        BigDecimal totalScore =
            weightedAverage(
                trendScore, ruleSet.trendWeight(),
                flowScore, ruleSet.flowWeight(),
                futuresProgramScore, ruleSet.futuresProgramWeight(),
                breadthScore, ruleSet.breadthWeight(),
                volatilityScore, ruleSet.volatilityWeight(),
                exchangeScore, ruleSet.exchangeWeight(),
                rateScore, ruleSet.rateWeight(),
                liquidityScore, ruleSet.liquidityWeight()
            );

        return new MarketScoreResult(
            clamp(totalScore),
            trendScore,
            flowScore,
            futuresProgramScore,
            breadthScore,
            volatilityScore,
            exchangeScore,
            rateScore,
            liquidityScore,
            calculateConfidence(input),
            buildReasons(input)
        );
    }
}

4. 시장국면 판정기
============================================================

4.1 기본 판정기준
------------------------------------------------------------

OVERHEATED
- 시장점수 80 이상
- 변동성 낮음
- 시장 확산도 높음
- 과열점수 또는 AI 피로점수 높음

NORMAL
- 시장점수 60 이상 80 미만

MILD_CORRECTION
- 시장점수 45 이상 60 미만

STRONG_CORRECTION
- 시장점수 25 이상 45 미만

CRASH_RISK
- 시장점수 25 미만
- 또는 별도 강제위험 조건 충족


4.2 강제위험 조건 예시
------------------------------------------------------------

다음 중 하나 이상이면 CRASH_RISK 가능
- 대표지수 일일 -5% 이하
- 시장 확산도 15 미만
- 변동성지수 급등
- 외국인 현물·선물 동시 대규모 매도
- 프로그램 비차익 대규모 매도
- 환율 급등
- 시스템리스크 이벤트
- 거래정지·서킷브레이커 등 비상상황

7. 현금비중 계산기
============================================================

7.1 전체 현금비중
------------------------------------------------------------

TOTAL_CASH
= CASH_AMT + RSV_CASH_AMT

CASH_RT
= TOTAL_CASH / TOT_AST_AMT × 100


7.2 일반현금비중
------------------------------------------------------------

NORMAL_CASH_RT
= CASH_AMT / TOT_AST_AMT × 100


7.3 대기현금비중
------------------------------------------------------------

RESERVE_CASH_RT
= RSV_CASH_AMT / TOT_AST_AMT × 100


7.4 상태 판정
------------------------------------------------------------

CASH_SHORTAGE
- 현재 현금비중 < 목표 현금비중 - 허용오차

NORMAL
- 허용범위 내

CASH_EXCESS
- 현재 현금비중 > 목표 현금비중 + 허용오차

11.1 기본 계산식
------------------------------------------------------------

RAW_REG_BUY_AMT
= BASE_BUY_AMT × FINAL_MULT

최종 추천금액

REG_BUY_AMT
= MIN(
    RAW_REG_BUY_AMT,
    종목별 최대 매수금액,
    계좌 남은 정기매수 예산,
    목표비중 부족금액
  )


11.2 최소금액 처리
------------------------------------------------------------

추천금액이 최소주문금액보다 작을 경우

정책 1
- 0원 처리
- 차액은 대기현금 적립

정책 2
- 최소금액으로 올림
- 단, 계좌 예산을 초과하지 않을 경우

권장안
- 소수점 매수 가능 계좌: 금액매수
- 소수점 매수 불가 계좌: 1주 가격과 비교
- 국내계좌와 해외계좌 정책 분리


11.3 수량 계산
------------------------------------------------------------

소수점 허용

BUY_QTY
= REG_BUY_AMT / CUR_PRC

소수점 불가

BUY_QTY
= FLOOR(REG_BUY_AMT / CUR_PRC)

실제 주문금액

ORDER_AMT
= BUY_QTY × CUR_PRC

- 정기매수 설정이 영구 삭제된 경우

27. Property 기반 테스트 권장
============================================================

검증할 불변조건

- 시장점수는 항상 0~100
- 신뢰도는 항상 0~100
- 최종배수는 항상 0 이상
- 추천매수금액은 항상 0 이상
- 추천매수 총액은 계좌 예산 이하
- 추가매수 총액은 대기현금 이하
- 종목 현재비중은 총자산이 양수일 때 0 이상
- 매수와 매도 신호가 동시에 발생하지 않음

도구 예시
- jqwik
- QuickTheories

# 주석
# 경계값이 많은 계산엔진은 예제 기반 테스트뿐 아니라
# property 기반 테스트가 효과적이다.

28. 성능 고려사항
============================================================

100개 종목 기준
- 메모리 내 계산 권장
- 종목별 DB 조회 금지
- 필요한 데이터를 한 번에 조회
- 계산 후 배치 저장

권장 흐름
1. 계좌별 보유종목 일괄조회
2. 최신 시세 일괄조회
3. 최신 지수 일괄조회
4. 메모리 Map 구성
5. 병렬계산 여부 검토
6. 결과 batch insert

# 주석
# 종목 100개 수준에서는 병렬화보다 단순성과 재현성이 중요하다.
# 먼저 단일 스레드 계산 후 성능을 측정한다.
