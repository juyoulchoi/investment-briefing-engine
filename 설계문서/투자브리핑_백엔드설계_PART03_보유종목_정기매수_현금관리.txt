투자 브리핑 Spring Boot 백엔드 설계
PART 03. 보유종목·정기매수·현금관리 상세설계
대상 테이블: TB_HOLD, TB_REG_BUY, TB_CASH_RSV, TB_CASH_HIS
============================================================

문서 목적
------------------------------------------------------------
이 문서는 투자 브리핑 시스템의 보유종목, 정기매수 설정,
추가매수 대기현금, 현금 증감 이력을 상세 설계한다.

대상 테이블
1. TB_HOLD     : 계좌별 보유종목
2. TB_REG_BUY  : 정기매수 설정
3. TB_CASH_RSV : 추가매수 대기현금
4. TB_CASH_HIS : 현금 증감 이력

이번 문서에서 연결하는 기존 계산식
- 평가금액
- 손익금액
- 손익률
- 계좌 총자산
- 계좌 현금비중
- 종목 현재비중
- 목표비중
- 비중상태
- 정기매수 기본금액
- 시장배수
- 종목보정배수
- 최종매수배수
- 추천 매수금액
- 정기매수 감액분
- 추가매수 대기현금
- 대기현금 적립 및 사용 이력

※ 계산 기준은 기존에 작성한 내용을 유지한다.
※ 이 문서에서는 계산 결과를 저장할 테이블과 컬럼을 확정한다.
※ 계좌별 현금과 대기현금은 서로 분리하며, 다른 계좌와 합산하지 않는다.


============================================================
1. 핵심 계산식과 저장 위치
============================================================

1.1 평가금액
------------------------------------------------------------
평가금액 = 보유수량 × 현재가 × 환율

국내종목
- 환율 = 1

해외종목
- 환율 = 원화 환산 환율

저장 위치
- TB_HOLD.EVL_AMT

관련 입력
- TB_HOLD.HOLD_QTY
- TB_HOLD.CUR_PRC
- TB_HOLD.EXCH_RT

# 주석
# EVL_AMT는 원화 환산 평가금액으로 저장한다.
# 원통화 평가금액은 ORG_EVL_AMT에 저장한다.


1.2 손익금액
------------------------------------------------------------
원통화 손익금액 = (현재가 - 평단가) × 보유수량
원화 손익금액 = 원통화 손익금액 × 환율

저장 위치
- TB_HOLD.ORG_PL_AMT
- TB_HOLD.PL_AMT

# 주석
# TB_HOLD.PL_AMT는 현재 보유분의 평가손익이다.
# 수수료와 세금을 포함한 실현손익은 향후 거래이력 테이블에서 관리한다.


1.3 손익률
------------------------------------------------------------
손익률 = ((현재가 - 평단가) / 평단가) × 100

평단가가 0이거나 NULL인 경우
- 계산 불가
- PL_RT는 NULL 처리 권장

저장 위치
- TB_HOLD.PL_RT


1.4 계좌 총자산
------------------------------------------------------------
계좌 총자산
= 일반현금 + 추가매수 대기현금 + 보유종목 평가금액 합계

관련 컬럼
- TB_ACCT.CASH_AMT
- TB_ACCT.RSV_CASH_AMT
- SUM(TB_HOLD.EVL_AMT)

# 주석
# 대기현금도 계좌 자산에는 포함한다.
# 실행 단계에서는 일반현금과 추가매수 전용현금을 구분한다.


1.5 계좌 현금비중
------------------------------------------------------------
계좌 현금비중
= ((일반현금 + 대기현금) / 계좌 총자산) × 100

일반현금비중
= (일반현금 / 계좌 총자산) × 100

대기현금비중
= (대기현금 / 계좌 총자산) × 100

# 주석
# 현금비중은 파생값이므로 TB_ACCT에 중복 저장하지 않는 것을 기본으로 한다.


1.6 종목 현재비중
------------------------------------------------------------
현재비중 = 종목 평가금액 / 계좌 총자산 × 100

저장 위치
- TB_HOLD.CUR_WGT


1.7 목표비중
------------------------------------------------------------
저장 위치
- TB_HOLD.TGT_WGT

검증
- 계좌별 목표비중 합계가 100을 초과하지 않아야 한다.
- 목표현금비중을 별도로 두면 종목 목표비중 합계는
  100 - 목표현금비중 이하로 관리한다.


1.8 비중상태
------------------------------------------------------------
비중비율 = 현재비중 / 목표비중

예시 기준
- UNDERWEIGHT: 현재비중 < 목표비중 × 0.8
- NORMAL: 목표비중 × 0.8 이상, 목표비중 × 1.2 이하
- OVERWEIGHT: 현재비중 > 목표비중 × 1.2

비중차이 = 현재비중 - 목표비중
비중초과율 = ((현재비중 - 목표비중) / 목표비중) × 100

저장 위치
- TB_HOLD.WGT_STS
- TB_HOLD.WGT_DIFF_RT

# 주석
# 비중초과 허용기준 20%는 설정값으로 관리한다.


1.9 정기매수 최종 배수
------------------------------------------------------------
기본 계산식
최종매수배수
= 시장기본배수 × 종목보정배수 × 비중보정배수 × 위험보정배수

기존 구현이 가산 방식이면 기존 계산식을 그대로 유지한다.

저장 위치
- TB_REG_BUY.MKT_MULT
- TB_REG_BUY.STK_ADJ_MULT
- TB_REG_BUY.WGT_ADJ_MULT
- TB_REG_BUY.RISK_ADJ_MULT
- TB_REG_BUY.FINAL_MULT
- TB_REG_BUY.RULE_VER_NO


1.10 추천 매수금액
------------------------------------------------------------
추천 매수금액 = 최소 매수금액 × 최종매수배수

최종 제한
추천 매수금액 = MIN(
    최대 매수금액,
    계좌 사용가능현금,
    증권사 주문 가능금액,
    계산 추천금액
)

중단 조건
- 사용자 일시정지
- 비중 과다 초과
- 펀더멘털 훼손
- 구조적 위험
- 정기매수 불가 종목
- 계좌 현금 부족

저장 위치
- TB_REG_BUY.RCMD_BUY_AMT
- TB_REG_BUY.ACT_SIG
- TB_REG_BUY.PAUSE_RSN


1.11 정기매수 감액분
------------------------------------------------------------
기준 예정금액 = 최소 매수금액 × 정상 기준배수
감액분 = MAX(기준 예정금액 - 추천 매수금액, 0)

저장 위치
- TB_REG_BUY.SAVED_AMT
- TB_CASH_RSV 적립
- TB_CASH_HIS 적립 이력

# 주석
# 같은 기준일과 같은 설정으로 중복 적립되지 않도록 IDEMP_KEY를 사용한다.

2. TB_HOLD 보유종목
============================================================

2.1 테이블 목적
------------------------------------------------------------
계좌별 보유종목의 수량, 평단가, 현재가, 평가금액, 손익,
목표비중, 현재비중, 비중상태를 관리한다.


2.2 PostgreSQL DDL
------------------------------------------------------------
CREATE TABLE TB_HOLD (
    HOLD_ID         BIGINT GENERATED BY DEFAULT AS IDENTITY,
    ACCT_ID         BIGINT                  NOT NULL,
    STK_ID          BIGINT                  NOT NULL,
    HOLD_QTY        NUMERIC(20,8)           NOT NULL DEFAULT 0,
    AVG_PRC         NUMERIC(20,6)           NOT NULL DEFAULT 0,
    CUR_PRC         NUMERIC(20,6),
    EXCH_RT         NUMERIC(20,6)           NOT NULL DEFAULT 1,
    ORG_EVL_AMT     NUMERIC(20,4),
    EVL_AMT         NUMERIC(20,4),
    ORG_PL_AMT      NUMERIC(20,4),
    PL_AMT          NUMERIC(20,4),
    PL_RT           NUMERIC(10,4),
    TGT_WGT         NUMERIC(7,4),
    CUR_WGT         NUMERIC(7,4),
    WGT_DIFF_RT     NUMERIC(10,4),
    WGT_STS         VARCHAR(20),
    RISK_GRADE      VARCHAR(20),
    HOLD_STS        VARCHAR(20)             NOT NULL DEFAULT 'ACTIVE',
    PRC_BASE_DT     DATE,
    CALC_DTTM       TIMESTAMP WITH TIME ZONE,
    MEMO            VARCHAR(1000),
    USE_YN          CHAR(1)                 NOT NULL DEFAULT 'Y',
    DEL_YN          CHAR(1)                 NOT NULL DEFAULT 'N',
    CRT_DTTM        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CRT_USR_ID      VARCHAR(50),
    UPD_DTTM        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UPD_USR_ID      VARCHAR(50),

    CONSTRAINT PK_TB_HOLD PRIMARY KEY (HOLD_ID),
    CONSTRAINT UK_TB_HOLD_01 UNIQUE (ACCT_ID, STK_ID),
    CONSTRAINT FK_TB_HOLD_01 FOREIGN KEY (ACCT_ID) REFERENCES TB_ACCT (ACCT_ID),
    CONSTRAINT FK_TB_HOLD_02 FOREIGN KEY (STK_ID) REFERENCES TB_STK (STK_ID),
    CONSTRAINT CK_TB_HOLD_01 CHECK (HOLD_QTY >= 0),
    CONSTRAINT CK_TB_HOLD_02 CHECK (AVG_PRC >= 0),
    CONSTRAINT CK_TB_HOLD_03 CHECK (CUR_PRC IS NULL OR CUR_PRC >= 0),
    CONSTRAINT CK_TB_HOLD_04 CHECK (EXCH_RT > 0),
    CONSTRAINT CK_TB_HOLD_05 CHECK (TGT_WGT IS NULL OR TGT_WGT BETWEEN 0 AND 100),
    CONSTRAINT CK_TB_HOLD_06 CHECK (CUR_WGT IS NULL OR CUR_WGT BETWEEN 0 AND 100),
    CONSTRAINT CK_TB_HOLD_07 CHECK (
        WGT_STS IS NULL OR WGT_STS IN ('UNDERWEIGHT', 'NORMAL', 'OVERWEIGHT')
    ),
    CONSTRAINT CK_TB_HOLD_08 CHECK (
        HOLD_STS IN ('ACTIVE', 'CLOSED', 'TRANSFER_PENDING')
    ),
    CONSTRAINT CK_TB_HOLD_09 CHECK (USE_YN IN ('Y', 'N')),
    CONSTRAINT CK_TB_HOLD_10 CHECK (DEL_YN IN ('Y', 'N'))
);

CREATE INDEX IDX_TB_HOLD_01 ON TB_HOLD (ACCT_ID);
CREATE INDEX IDX_TB_HOLD_02 ON TB_HOLD (STK_ID);
CREATE INDEX IDX_TB_HOLD_03 ON TB_HOLD (WGT_STS);
CREATE INDEX IDX_TB_HOLD_04 ON TB_HOLD (RISK_GRADE);
CREATE INDEX IDX_TB_HOLD_05 ON TB_HOLD (USE_YN, DEL_YN);

2.4 Java Entity 핵심 예시
------------------------------------------------------------
@Entity
@Table(
    name = "TB_HOLD",
    uniqueConstraints = @UniqueConstraint(
        name = "UK_TB_HOLD_01",
        columnNames = {"ACCT_ID", "STK_ID"}
    )
)
@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder
public class TbHold {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "HOLD_ID")
    private Long holdingId;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "ACCT_ID", nullable = false)
    private TbAcct account;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "STK_ID", nullable = false)
    private TbStk stock;

    @Column(name = "HOLD_QTY", nullable = false, precision = 20, scale = 8)
    private BigDecimal holdingQuantity;

    @Column(name = "AVG_PRC", nullable = false, precision = 20, scale = 6)
    private BigDecimal averagePrice;

    @Column(name = "CUR_PRC", precision = 20, scale = 6)
    private BigDecimal currentPrice;

    @Column(name = "EXCH_RT", nullable = false, precision = 20, scale = 6)
    private BigDecimal exchangeRate;

    @Column(name = "EVL_AMT", precision = 20, scale = 4)
    private BigDecimal evaluationAmount;

    @Column(name = "PL_AMT", precision = 20, scale = 4)
    private BigDecimal profitLossAmount;

    @Column(name = "PL_RT", precision = 10, scale = 4)
    private BigDecimal profitLossRate;

    @Column(name = "TGT_WGT", precision = 7, scale = 4)
    private BigDecimal targetWeight;

    @Column(name = "CUR_WGT", precision = 7, scale = 4)
    private BigDecimal currentWeight;

    @Enumerated(EnumType.STRING)
    @Column(name = "WGT_STS", length = 20)
    private WeightStatus weightStatus;
}

CREATE TABLE TB_REG_BUY (

    CONSTRAINT FK_TB_REG_BUY_02 FOREIGN KEY (STK_ID) REFERENCES TB_STK (STK_ID),

        BUY_DAY_CD IS NULL OR BUY_DAY_CD IN ('MON', 'TUE', 'WED', 'THU', 'FRI')

    CONSTRAINT CK_TB_REG_BUY_03 CHECK (BUY_DAY_NO IS NULL OR BUY_DAY_NO BETWEEN 1 AND 31),

    CONSTRAINT CK_TB_REG_BUY_05 CHECK (MAX_BUY_AMT IS NULL OR MAX_BUY_AMT >= MIN_BUY_AMT),

    CONSTRAINT CK_TB_REG_BUY_07 CHECK (FINAL_MULT IS NULL OR FINAL_MULT >= 0),
    CONSTRAINT CK_TB_REG_BUY_08 CHECK (RCMD_BUY_AMT IS NULL OR RCMD_BUY_AMT >= 0),
    CONSTRAINT CK_TB_REG_BUY_09 CHECK (SAVED_AMT IS NULL OR SAVED_AMT >= 0),
    CONSTRAINT CK_TB_REG_BUY_10 CHECK (
        ACT_SIG IS NULL OR ACT_SIG IN (
            'PAUSE', 'REDUCE', 'KEEP_MINIMUM', 'INCREASE', 'ADDITIONAL_BUY', 'REBUY'
        )
    ),
    CONSTRAINT CK_TB_REG_BUY_11 CHECK (BUY_STS IN ('ACTIVE', 'PAUSED', 'STOPPED')),
    CONSTRAINT CK_TB_REG_BUY_12 CHECK (USER_PAUSE_YN IN ('Y', 'N')),
    CONSTRAINT CK_TB_REG_BUY_13 CHECK (AUTO_CALC_YN IN ('Y', 'N')),
    CONSTRAINT CK_TB_REG_BUY_14 CHECK (USE_YN IN ('Y', 'N')),
    CONSTRAINT CK_TB_REG_BUY_15 CHECK (DEL_YN IN ('Y', 'N'))

4. TB_CASH_RSV 추가매수 대기현금
============================================================

4.1 설계 기준
------------------------------------------------------------
TB_CASH_RSV는 계좌별 추가매수 전용 대기현금의 현재 잔액을 관리한다.

# 주석
# 권장안은 TB_CASH_RSV를 원장성 잔액 테이블로 사용하는 것이다.
# TB_ACCT.RSV_CASH_AMT는 조회 편의를 위한 캐시 값으로 두고 같은 트랜잭션에서 동기화한다.


4.2 PostgreSQL DDL
------------------------------------------------------------
CREATE TABLE TB_CASH_RSV (
    CASH_RSV_ID     BIGINT GENERATED BY DEFAULT AS IDENTITY,
    ACCT_ID         BIGINT                  NOT NULL,
    RSV_AMT         NUMERIC(20,4)           NOT NULL DEFAULT 0,
    ACCUM_AMT       NUMERIC(20,4)           NOT NULL DEFAULT 0,
    USED_AMT        NUMERIC(20,4)           NOT NULL DEFAULT 0,
    LAST_TX_DT      DATE,
    VER_NO          BIGINT                  NOT NULL DEFAULT 0,
    CRT_DTTM        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CRT_USR_ID      VARCHAR(50),
    UPD_DTTM        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UPD_USR_ID      VARCHAR(50),

    CONSTRAINT PK_TB_CASH_RSV PRIMARY KEY (CASH_RSV_ID),
    CONSTRAINT UK_TB_CASH_RSV_01 UNIQUE (ACCT_ID),
    CONSTRAINT FK_TB_CASH_RSV_01 FOREIGN KEY (ACCT_ID) REFERENCES TB_ACCT (ACCT_ID),
    CONSTRAINT CK_TB_CASH_RSV_01 CHECK (RSV_AMT >= 0),
    CONSTRAINT CK_TB_CASH_RSV_02 CHECK (ACCUM_AMT >= 0),
    CONSTRAINT CK_TB_CASH_RSV_03 CHECK (USED_AMT >= 0)
);

CREATE INDEX IDX_TB_CASH_RSV_01 ON TB_CASH_RSV (ACCT_ID);

5. TB_CASH_HIS 현금 증감 이력
============================================================

5.1 설계 기준
------------------------------------------------------------
일반현금과 대기현금이 증가하거나 감소한 모든 이력을 저장한다.

거래 유형
- DEPOSIT
- WITHDRAW
- REG_BUY_SAVE
- ADD_BUY_USE
- MANUAL_ADJUST
- TRANSFER_IN
- TRANSFER_OUT

# 주석
# 이력은 수정·삭제하지 않고 반대 거래로 정정한다.
# 중복 실행 방지를 위해 IDEMP_KEY를 UNIQUE로 사용한다.


5.2 PostgreSQL DDL
------------------------------------------------------------
CREATE TABLE TB_CASH_HIS (
    CASH_HIS_ID     BIGINT GENERATED BY DEFAULT AS IDENTITY,
    ACCT_ID         BIGINT                  NOT NULL,
    REG_BUY_ID      BIGINT,
    TX_DT           DATE                    NOT NULL,
    CASH_TP         VARCHAR(20)             NOT NULL,
    TX_TP           VARCHAR(30)             NOT NULL,
    IN_OUT_TP       VARCHAR(10)             NOT NULL,
    TX_AMT          NUMERIC(20,4)           NOT NULL,
    BAL_BFR_AMT     NUMERIC(20,4)           NOT NULL,
    BAL_AFT_AMT     NUMERIC(20,4)           NOT NULL,
    IDEMP_KEY       VARCHAR(100)            NOT NULL,
    REF_TBL_NM      VARCHAR(50),
    REF_ID          BIGINT,
    TX_RSN          VARCHAR(500),
    CRT_DTTM        TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CRT_USR_ID      VARCHAR(50),

    CONSTRAINT PK_TB_CASH_HIS PRIMARY KEY (CASH_HIS_ID),
    CONSTRAINT UK_TB_CASH_HIS_01 UNIQUE (IDEMP_KEY),
    CONSTRAINT FK_TB_CASH_HIS_01 FOREIGN KEY (ACCT_ID) REFERENCES TB_ACCT (ACCT_ID),
    CONSTRAINT FK_TB_CASH_HIS_02 FOREIGN KEY (REG_BUY_ID) REFERENCES TB_REG_BUY (REG_BUY_ID),
    CONSTRAINT CK_TB_CASH_HIS_01 CHECK (CASH_TP IN ('NORMAL', 'RESERVE')),
    CONSTRAINT CK_TB_CASH_HIS_02 CHECK (
        TX_TP IN (
            'DEPOSIT', 'WITHDRAW', 'REG_BUY_SAVE', 'ADD_BUY_USE',
            'MANUAL_ADJUST', 'TRANSFER_IN', 'TRANSFER_OUT'
        )
    ),
    CONSTRAINT CK_TB_CASH_HIS_03 CHECK (IN_OUT_TP IN ('IN', 'OUT')),
    CONSTRAINT CK_TB_CASH_HIS_04 CHECK (TX_AMT > 0),
    CONSTRAINT CK_TB_CASH_HIS_05 CHECK (BAL_BFR_AMT >= 0),
    CONSTRAINT CK_TB_CASH_HIS_06 CHECK (BAL_AFT_AMT >= 0)
);

CREATE INDEX IDX_TB_CASH_HIS_01 ON TB_CASH_HIS (ACCT_ID, TX_DT DESC);
CREATE INDEX IDX_TB_CASH_HIS_02 ON TB_CASH_HIS (REG_BUY_ID);
CREATE INDEX IDX_TB_CASH_HIS_03 ON TB_CASH_HIS (TX_TP, TX_DT DESC);

6. 현금 적립 및 사용 서비스 처리 순서
============================================================

6.1 정기매수 감액분 적립
------------------------------------------------------------
1. TB_REG_BUY 계산 결과 조회
2. SAVED_AMT > 0 확인
3. IDEMP_KEY 생성
4. 동일 IDEMP_KEY 존재 여부 확인
5. TB_CASH_RSV 잠금 조회
6. 거래 전 잔액 계산
7. RSV_AMT와 ACCUM_AMT 증가
8. TB_ACCT.RSV_CASH_AMT 동기화
9. TB_CASH_HIS에 REG_BUY_SAVE 저장
10. 하나의 트랜잭션으로 커밋

멱등성 키 예시
REG_BUY_SAVE:{기준일}:{REG_BUY_ID}


6.2 추가매수 대기현금 사용
------------------------------------------------------------
1. 계좌 대기현금 조회
2. 추천금액보다 잔액이 충분한지 확인
3. IDEMP_KEY 중복 확인
4. TB_CASH_RSV.RSV_AMT 감소
5. TB_CASH_RSV.USED_AMT 증가
6. TB_ACCT.RSV_CASH_AMT 동기화
7. TB_CASH_HIS에 ADD_BUY_USE 저장
8. 추가매수 실행 여부 저장
9. 하나의 트랜잭션으로 커밋
