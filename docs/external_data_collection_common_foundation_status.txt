Investment Briefing Engine
3.1 외부 데이터 수집 공통 기반 개발 현황
===========================================

1. 조사 기준
-----------

- 기준 프로젝트: investment-briefing-engine
- 기준 브랜치: main
- 판정 기준: 클래스 존재 여부뿐 아니라 실제 호출 경로, 저장, 상태 관리 연결 여부
- 판정 구분:
  - 완료: 현재 프로젝트에서 실제 호출·저장 가능한 상태
  - 부분 개발: 일부 기반은 있으나 운영 요구사항이 완성되지 않은 상태
  - 미개발: 관련 클라이언트·서비스·Job 또는 실제 호출 연결이 없는 상태


2. 전체 결과
-----------

- 완료: 13개
- 부분 개발: 7개
- 미개발: 2개
- 추가 개발이 필요한 항목: 부분 개발 7개 + 미개발 2개 = 총 9개

16. 공급자별 connect/read timeout
    상태: 부분 개발
    현재 구현:
    - 공통 connect timeout 기본 3초
    - 공통 read timeout 기본 10초
    - FRED 전용 HTTP/1.1 클라이언트
    - FRED 전용 connect timeout 기본 5초
    - FRED 전용 read timeout 기본 30초
    부족한 기능:
    - KRX/Yahoo/KOFIA 등 나머지 공급자별 개별 timeout
    - Dataset 또는 호출 종류별 timeout
    - 설정 변경 시 공급자별 독립 적용

17. 공급자별 재시도 정책
    상태: 부분 개발
    현재 공통 정책:
    - 최대 호출 횟수 4회
    - 약 1초, 3초, 10초 backoff
    - 0.8~1.2 jitter
    - Retry-After 우선 적용
    - 재시도 가능한 HTTP/네트워크 오류 선별
    부족한 기능:
    - 공급자별 최대 횟수
    - 공급자별 backoff
    - 공급자별 재시도 HTTP 상태
    - API 호출량/rate limit 정책
    - Dataset별 비재시도 오류 코드

18. Circuit Breaker
    상태: 부분 개발
    현재 구현:
    - 공급자 key별 실패 수 관리 클래스
    - 실패 임계치 도달 시 open
    - open 기간 호출 차단
    - 성공 시 실패 수 초기화
    - 단위 테스트 존재
    부족한 기능:
    - FRED 실제 호출 경로에는 연결 완료
    - KRX/Yahoo 실제 호출 경로에는 연결되지 않음
    - 공급자별 설정 외부화 없음
    - 다중 인스턴스 상태 공유 없음
    - half-open 시험 호출 관리 없음
    - 관리자 상태 조회 및 강제 해제 없음

7. KRX 기간 백필 오케스트레이터 설명
-----------------------------------

KRX는 baseDate 한 날짜 Job과 from~to 기간 상위 Job을 모두 지원한다.

예:

  POST /api/v1/krx/collection-jobs?baseDate=2024-01-02

기간 백필 오케스트레이터는 다음 요청을 하나의 상위 Job으로 관리한다.

  from = 2024-01-01
  to   = 현재 날짜

현재 구현된 처리:

  기간 Job 생성
    -> 대상 거래일 계산
    -> 날짜별 하위 Collection Job 생성
    -> Dataset별 호출
    -> 전체 진행률 저장
    -> 실패 날짜/Dataset 기록
    -> 중단 지점 재개
    -> 실패 항목만 재처리

이 기능은 새로운 KRX API Dataset 신청이 아니라, 이미 승인된 KRX Dataset의 과거
데이터를 안정적으로 수집하기 위한 프로젝트 내부 운영 기능이다.

10. 최종 결론
-------------

현재 프로젝트는 KRX 8개 Dataset, Yahoo 지수/해외종목/환율, FRED 채권금리와
DB 등록형 범용 FRED Macro Series의 기간 수집·Job·관측값·정정이력 저장까지 구현되어 있다.

추가 API 신청 관점에서는 투자자별 EOD 데이터와 KOFIA 데이터 확보가 핵심이다.

프로젝트 내부 개발 관점에서는 KRX/Yahoo까지 공급자별 resilience와 호출 로그를
확장하고, 공통 Dead Letter, 휴장·미발표 판별, 정정 후 downstream 재계산을 연결하는
작업이 핵심 미완성 영역이다.
