1. 작업 목표
-----------

- DB를 투자 브리핑의 Source of Truth로 사용한다.
- OpenAI는 DB에서 확정된 숫자, 점수, 확률, 등급, 신호를 재계산하거나 변경하지 않는다.
- OpenAI는 DB 확정값을 사용자가 이해하기 쉽게 설명하는 역할만 담당한다.
- 일일 브리핑과 주간 브리핑이 동일한 15개 항목의 번호, 코드, 제목, 순서를 사용한다.
- DB 확정값과 OpenAI 결과가 다르면 브리핑을 발행하지 않는다.
- 1~4주 시장방향 예측 점수와 네 시나리오 확률을 DB에 저장한다.
- 브리핑의 정수/소수/환율/원화 금액 표시 규칙을 통일한다.


2. 핵심 설계 변경
----------------

변경 전:

DB 원천데이터
-> OpenAI가 브리핑 생성
-> 항목 코드와 날짜 중심 검증
-> 저장 및 발행

문제점:

- OpenAI가 DB와 다른 숫자나 신호를 생성할 수 있었다.
- 일일/주간 항목 구성이 달라질 수 있었다.
- 시장방향 예측 결과의 전용 DB 저장소가 없었다.
- OpenAI 응답과 DB 확정값을 직접 비교하지 않았다.

변경 후:

시장데이터 수집
-> DB 정합성 검증
-> 시장 Snapshot 생성
-> 시장심리 계산
-> 투자판단 계산
-> 추가매수/재매수 계산
-> 시장방향 예측 계산 및 DB 저장
-> TB_BRF 브리핑 Snapshot 확정
-> OpenAI 설명 생성
-> DB confirmedValues 완전 동일성 검증
-> 검증 성공 시에만 발행

핵심 책임:

DB = 숫자, 점수, 확률, 등급, 신호, 행동판단의 최종 권한
OpenAI = DB 확정값 설명 전용

4.1 신규 테이블 TB_MKT_DIR_PRED

용도:

- DB에서 확정한 1~4주 시장방향 예측 저장
- 네 시나리오 확률 저장
- 직전 예측 대비 확률 변화 저장
- 계산 입력별 원천데이터 기준일 저장
- 계산 근거 및 규칙 버전 저장
- 같은 기준일의 계산 이력과 최신값 구분

주요 컬럼:

UPTREND_RESUME_PROB      상승추세 재개 확률

RE_CORRECTION_PROB       재조정 확률
RETEST_LOW_PROB          전저점 재시험 확률
UPTREND_RESUME_CHG       상승추세 재개 확률 변화 %p
BOX_RANGE_CHG            박스권 확률 변화 %p
RE_CORRECTION_CHG        재조정 확률 변화 %p
RETEST_LOW_CHG           전저점 재시험 확률 변화 %p
INPUT_BASE_DT_JSON       계산 입력별 원천데이터 기준일 JSON
CALC_BASIS_JSON          계산 근거 JSON
RULE_VER_NO              계산규칙 버전
LATEST_YN                같은 기준일의 최신 계산 여부

DB 제약:

- DIR_SCR은 0~100
- 네 시나리오 확률은 각각 0~100
- 네 시나리오 확률 합계는 정확히 100
- LATEST_YN은 Y 또는 N
- 같은 BASE_DT의 LATEST_YN=Y 행은 한 건만 허용
- BASE_DT + CALC_SEQ 중복 금지

6. OpenAI 요청 및 응답 변경
--------------------------

OpenAI 시스템 지침에 다음 원칙을 포함했다.

"DB에서 전달된 숫자, 점수, 확률, 등급, 신호, 계좌별 행동판단은 확정값이다.
이 값을 재계산하거나 변경하지 않는다.
OpenAI의 역할은 DB 값을 근거로 사용자가 이해하기 쉬운 설명을 생성하는 것이다.
DB 값과 다른 숫자나 신호를 생성하지 않는다.
데이터가 없는 경우 임의 추정하지 않고 '데이터 부족'이라고 표시한다."

추가 규칙:

- confirmedValues는 입력 JSON의 값을 그대로 복사한다.
- 15개 항목을 정확히 한 번씩 작성한다.
- 항목 코드, 제목, 순서를 변경하지 않는다.
- DAILY/WEEKLY 모두 동일한 항목 제목을 사용한다.
- WEEKLY는 내용만 다음 주 관점으로 작성한다.
- 데이터에 없는 뉴스나 일정을 만들지 않는다.
- 사실과 해석을 구분한다.
- 매수/매도 권유가 아니라 DB 계산 결과 설명으로 작성한다.
- 정수 점수와 확률에 불필요한 소수점을 붙이지 않는다.

7. Validation 변경
-----------------

BriefingValidationService에서 발행 전 다음을 검증한다.

1. 브리핑 항목이 정확히 15개인지 확인
2. 항목 코드가 기준과 일치하는지 확인
3. 항목 순서가 일치하는지 확인
4. 각 항목의 한국어 제목이 일치하는지 확인
5. 시장 위험지수가 0~100인지 확인
6. 시장방향예측지수가 0~100인지 확인
7. 네 시나리오 확률이 각각 0~100인지 확인
8. 네 시나리오 확률 합계가 정확히 100인지 확인
9. DB 기준일과 OpenAI 기준일이 같은지 확인
10. 요청 타입, DB 타입, OpenAI 타입이 같은지 확인
11. DB confirmedValues와 OpenAI confirmedValues 전체 JSON이 완전히 같은지 확인
12. 필수 설명과 신호가 존재하는지 확인
13. 신호 코드가 허용 범위인지 확인

검증 실패 시:

BRF_STS = FAILED
PUBL_YN = N
FAIL_RSN = 검증 실패 원인
UPD_USR_ID = VALIDATOR

상세 항목을 저장하거나 발행하지 않고 예외를 반환한다.

9. 시장방향 예측 초기 계산
-------------------------

현재 DB에 안정적으로 저장된 값을 사용한다.

입력:

- TB_INV_DEC.MKT_SCR
- TB_INV_DEC.RISK_SCR
- TB_INV_DEC.MKT_REGIME

현재 방향예측지수 계산식:

marketDirectionScore =
  (marketScore + (100 - marketRiskScore)) / 2

네 시나리오의 초기 가중치를 계산한 후 정수 확률로 정규화한다.

정규화 조건:

- 각 확률은 0~100
- 합계는 정확히 100
- 나눗셈 반올림 오차는 마지막 시나리오에서 보정

직전 최신 예측과 비교해 네 확률 변화 %p를 저장한다.

13. 현재 Git 작업 트리 주의사항
------------------------------

커밋 67a2180에는 브리핑 개편 파일만 포함했다.

현재 작업 트리에는 별도 보유종목, 비중, 프런트엔드 변경이 남아 있다.

예:

- backend/src/main/java/com/nanum/investment/common/...
- backend/src/main/java/com/nanum/investment/holding/...
- frontend/src/OperationsAdmin.tsx
- frontend/src/main.tsx
- V98~V101 migration

이 파일들은 67a2180 브리핑 커밋에 포함되지 않았다.

이번 작업의 정확한 diff는 다음 명령으로 확인한다.

git diff 67a2180^ 67a2180

현재 git status 전체를 이번 브리핑 작업 파일로 해석하면 안 된다.


14. Git diff 확인 명령
---------------------

커밋 요약:

git show --stat 67a2180

변경 파일 상태:

git show --name-status 67a2180

전체 코드 diff:

git show --no-ext-diff --no-renames 67a2180

부모 커밋과 직접 비교:

git diff 67a2180^ 67a2180

DB 변경만 확인:

git diff 67a2180^ 67a2180 -- backend/src/main/resources/db/migration/V102__make_briefing_database_source_of_truth.sql

브리핑 Java 변경만 확인:

git diff 67a2180^ 67a2180 -- backend/src/main/java/com/nanum/investment/briefing

파이프라인 변경만 확인:

git diff 67a2180^ 67a2180 -- backend/src/main/java/com/nanum/investment/marketdata/application/BriefingRefreshService.java
