# 거래량 증가·횡보 후보 검색 V1

## 구현 범위

- 메뉴: **거래량·횡보 검색**. 날짜별 코스피·코스닥 후보, 제외 종목, 종목 검색, 시장 필터, 상세 지표, 제외 사유 집계를 제공한다.
- 조회 API: `GET /api/v1/krx/screens/volume-consolidation?baseDate=YYYY-MM-DD`
- 추적 API: `GET /api/v1/krx/screens/volume-consolidation/tracking?market=KOSPI&stockCode=005930&selectionDate=YYYY-MM-DD&asOf=YYYY-MM-DD`
- 기본 조회일은 Asia/Seoul 기준 어제다. 원본 저장소에 종가 확정 플래그가 없어 오늘 및 미래 날짜를 거부한다. 요청일, 실제 계산 기준일, 관찰·비교 시작일을 구분해 반환한다.
- 시세 원본은 읽기만 하며, 수집 후 자동 검색 결과와 실행 이력은 V150의 `TB_VOL_CONSOL_RUN`에 저장한다. 자동주문은 수행하지 않는다.
- 거래 예산·주문 수량 자동 계산, 수급 수집, 공시 수집, 수익률 백테스트는 이 기능에 포함하지 않는다.

## 수치 조건

`T`는 계산 기준일, 날짜 인덱스는 오름차순인 75개 저장 거래일이다.

| 지표 | 정의 | 통과 조건 |
|---|---|---|
| 관찰 구간 | T−14 ~ T, 인덱스 60~74 | 15일 |
| 비교 구간 | T−74 ~ T−15, 인덱스 0~59 | 관찰 구간과 겹치지 않는 60일 |
| 3주 수익률 | (C[T] / C[T−15] − 1) × 100 | −5% 이상 +5% 이하 |
| 종가 횡보 폭 | (관찰 구간 최고 종가 / 최저 종가 − 1) × 100 | 10% 이하 |
| 평균 거래량 배수 | 관찰 구간 평균 / 비교 구간 평균 | 2배 이상 |
| 거래량 증가율 | (위 배수 − 1) × 100 | 표시용: 2배는 100% 증가 |
| 일별 거래량 배수 | V[d] / d 직전 20일 평균. d 당일 제외 | 5배 이상 1일 이상, 2배 이상 3일 이상 |
| 평균 거래대금 | 관찰 구간 거래대금 평균, 원 단위 | 20억원 이상 |

종목 기본정보 `ISU_SRT_CD`와 일별시세 `ISU_CD`를 시장+단축코드로 연결한다. 기본정보는 기준일 이하에서 시장별 최신 스냅샷만 사용한다. 보통주(`KIND_STKCERT_TP_NM=보통주`, `SECUGRP_NM=주권`) 확인 불가 및 그 외 종류는 제외한다. 코스피·코스닥 주식 일별 데이터만 읽으므로 ETF/ETN 별도 데이터셋은 대상이 아니다.

확인된 SPAC/스팩·위험 지정, 75일 중 누락·중복, 잘못된 OHLC, 0 이하 거래량·거래대금, 상장주식수 미확인·변동은 제외한다. 상장주식수 변동 제외는 분할·증자 등의 왜곡을 줄이기 위한 보수적인 초기 규칙이다. 원본은 수정주가가 아니며 주식수 변화가 없는 기업행사까지 탐지하는 것은 아니다.

정렬: 조건 통과 우선 → 거래량 2배 지속일수 내림차순 → 평균 거래량 배수 내림차순 → 종가 횡보 폭 오름차순 → 시장·종목코드. 계산은 BigDecimal을 사용한다. 표시 반올림값으로 통과 여부를 판단하지 않는다.

## 데이터 품질과 검증 경계

- `quantitativeMatch`는 저장 데이터로 계산한 조건 통과 여부다. `REQUIRES_VERIFICATION`은 매수 승인 또는 매집 확정을 뜻하지 않는다.
- `TB_MKT_CAL`의 알려진 개장일과 코스피·코스닥 주식/지수 날짜를 함께 이용하여 한 소스에만 있는 날짜도 누락 검출에 포함한다.
- 기간 내 평일에 주식·지수 시세가 모두 없고 달력에도 휴장(`N`)이 없으면 `unverifiedWeekdays`로 반환한다. 휴장일일 수 있으므로 모두 수집 누락으로 단정하지 않는다.
- 위 날짜가 있으면 `dateCoverageStatus=DATE_GAPS_UNVERIFIED`다. 지표와 통과 수는 **저장일 기준 잠정 계산**으로 표시한다. 날짜 공백 확인 전 실제 최근 15거래일 결과로 확정하거나 돌파 추적을 실행하지 않는다.
- `NO_UNEXPLAINED_GAPS`도 시장 전체 종목 파일의 완전성이나 공식 종가 확정 인증을 뜻하지 않는다. 종목별 날짜·가격 품질 검증을 별도로 적용한다.
- Main에는 종목별 투자자 순매수 연결이 없어 금액을 `null`, `flowStatus=UNAVAILABLE`로 반환한다. 공시는 `NOT_CHECKED`다. 미확인을 0으로 대체하지 않는다.
- 관리·투자주의·정리매매·거래정지 전체를 확정할 상태 이력이 없어 최종 검증이 필요하다. 현재 자료에서 위험 상태가 확인되는 경우는 제외한다.
- 과거 날짜 조회는 현재 저장된 정정 원본으로 계산한다. 원본의 당시 이용 가능 시각을 복원하는 백테스트가 아니다.

## 고정 박스 추적

선정일의 15일 최고 **고가**, 최저 **저가**를 고정한다. 이후 시세로 상단을 다시 계산하지 않는다.

1. 선정일 다음 거래일부터 10거래일 이내, 종가가 상단을 **초과**하고 거래량이 직전 20일 평균의 2배 이상이면 `BREAKOUT`.
2. 돌파 다음 거래일부터 5거래일 이내, 저가가 상단의 99%~101% 안에 있고 종가가 상단 이상이면 `RETEST_HELD`.
3. 돌파 이후 종가가 상단 미만이면 `FAILED`. 상단과 같은 종가는 실패로 보지 않는다.
4. 10번째 거래일까지 돌파가 없으면 `EXPIRED`. 그 이후 돌파를 기존 후보의 신호로 인정하지 않는다.
5. 종목 시세 누락·거래 없음·상장주식수 변화가 발생하면 `DATA_UNAVAILABLE`로 중단한다. 미확인 평일이 포함되면 API에서 추적 요청 자체를 거부한다.
6. 선정일은 조회일 이전 1년 이내로 제한한다. 이벤트는 종가 확인 시점이며 당일 종가 체결을 가정하지 않는다. 이후 재선정 시 새 선정일을 명시한다.

## 2026-10-04: 수집 후 자동 검색과 KOFIA 오전 수집

### 실행 순서

- 월~금 08:20 일일 브리핑, 토요일 08:20 주간 판단의 국내 시세 수집이 끝나면 `HoldingMarketDataRefreshService`가 `VolumeConsolidationRunService.afterCollection`을 호출한다.
- 코스피·코스닥·ETF·코스피지수가 모두 수집된 실제 기준일을 전달한다. 해외 시세나 이후 브리핑 생성 실패 여부와 독립적으로 검색 결과를 남긴다.
- 수집 실패는 `SKIPPED`, 검색/저장 실패는 `FAILED`로 기록하며 검색 실패가 기존 브리핑 진행을 막지 않는다. 재시작 이전에 남은 `RUNNING` 이력은 실패로 정리한다.
- 날짜 공백·자료 부족은 `PARTIAL`, 수치 계산 완료는 `CALCULATED`다. 후자도 매집·매수 검증 완료를 의미하지 않는다.
- 정기 실행 외에 ‘브리핑 갱신’에서도 같은 수집 완료 경로를 사용한다. 개별 KRX 원본 API 호출이나 과거 일괄수집 항목마다 후보 검색을 반복하지는 않는다.
- 국내 시세가 당일 기준인 수동 오후 갱신은 기존 검색기의 종가 확정 제한에 따라 `SKIPPED`로 남기고 다음 아침 검색한다.
- 검색 결과는 매 실행 별도 UUID로 저장한다. 같은 시세 기준일을 재조회해도 이전 결과를 덮어쓰지 않는다.

### KOFIA 시간 및 대상일

모든 시간은 `Asia/Seoul`, cron은 `0 20 8 * * MON-SAT`이다. 활성화 설정과 기존 조건별 수집 범위는 유지한다.

| 작업 | 오전 수집 대상 |
|---|---|
| 공통 시장 데이터 + 업종/회사 기준정보 | 시장 데이터는 전일까지 최근 21일(기존 overlap-days 설정), 기준정보는 실행 시 조회 |
| 기간자금유출입 | 전일까지 최근 21일, 활성 조합 |
| 고객유형별규모 | 전월 월말 자료, 활성 조합 |
| 회사별자금유출입 | 직전 평일 1일, 활성 조합. 월요일·토요일에는 금요일 |

회사별 수집일은 주말을 제외한 직전 평일이며 공식 휴장 달력 판정이 아니다. 휴장일 빈 응답은 기존 수집 결과 상태로 구분한다. 수집 API 지연·요청 제한·이미 실행 중인 작업 때문에 실제 처리 완료 시각은 달라질 수 있다.

브리핑과 KOFIA 네 작업이 같은 시각에 실행될 수 있도록 `spring.task.scheduling.pool.size=5`를 설정했다. KOFIA의 비동기 수집 작업 풀과 요청 간격 제한은 기존 설정을 유지한다.

추가 검증은 토요일 실행·일요일 제외, 월요일 회사별 대상일, 수집→후보 검색→해외/지수 처리 순서, 실패 격리, 임시 PostgreSQL 테이블에서 V150 및 결과 직렬화/조회/복구 동작을 포함한다.
