DATASET_V1 FROZEN BASELINE 및 CORE / SUPPLEMENT / FUTURE 분류
================================================================

작성 기준일: 2026-08-31 (Asia/Seoul)
대상 프로젝트: investment-briefing-engine
대상 환경: Main
대상 브랜치: main
기준 DB: investment-postgres / investment
연결 구조: LEGACY → RECALC → OUTCOME


1. 목적
-------

현재 단계에서는 새로운 외부 API를 계속 추가하기보다 Main DB에 실제로
안정적으로 적재되고 있는 데이터를 기준으로 DATASET_V1을 동결한다.

DATASET_V1을 이용하여 다음 한 사이클을 먼저 완성한다.

현재 확보 데이터
    ↓
알고리즘 v2
    ↓
계산 및 투자판단
    ↓
과거 전체 RECALC
    ↓
OUTCOME 비교
    ↓
성능 측정

새로운 지표가 추가되어 알고리즘 v3, v4로 발전하더라도 같은 과거 Case와
같은 DATASET_V1을 사용하여 다시 계산할 수 있어야 한다.

예:

알고리즘 v2
- 시장위험점수: 72
- 판단: 추가매수 중단

알고리즘 v3
- 시장위험점수: 81
- DELEVERAGING_RISK: 78
- 판단: 현금비중 확대

동일한 과거 날짜에 대해 v2와 v3를 각각 재계산하고 실제 이후
D+1, D+5, D+10, D+20, D+60 거래일 성과와 비교한다.

이를 통해 v3가 v2보다 실제 하락 위험을 더 빨리 잡았는지 검증한다.


2. Frozen Baseline의 의미
--------------------------

DATASET_V1을 동결한다는 것은 일별 수집을 중단한다는 뜻이 아니다.

다음 계약을 고정한다는 뜻이다.

- 포함 지표 목록
- 지표 코드
- 공급자
- 저장 테이블
- 계산 의미
- 필수 또는 선택 여부
- 결측 처리 정책
- 계산 규칙에서의 역할
- 데이터셋 버전
- 알고리즘 버전과의 조합

동일한 공급자, 동일한 필드 계약, 동일한 의미로 일별 데이터가 추가되는
것은 DATASET_V1의 연장이다.

다음 중 하나가 바뀌면 DATASET_V2로 승격하는 것을 원칙으로 한다.

- 신규 외부 데이터가 정식 포함됨
- 공급자가 변경됨
- 지표 정의 또는 계산 의미가 변경됨
- 원천 필드 계약이 변경됨
- Point-in-time 또는 vintage 정책이 새로 적용됨
- 기존에 없던 투자자 수급이나 뉴스심리 등이 포함됨


3. 판정 기준
------------

3.1 CORE

현재 알고리즘의 계산, 판단, 브리핑, RECALC, OUTCOME 사이클을 실행하는 데
직접 필요하며 실제 Main DB에서 역사 데이터가 확인되는 항목이다.

3.2 SUPPLEMENT

Main DB에 실제 데이터가 있고 역사 길이도 충분하지만 현재 알고리즘의
핵심 점수에 아직 직접 사용되지 않거나 의미와 규칙을 추가 확정해야 하는
항목이다.

3.3 FUTURE

필요성 또는 DB 컬럼만 존재할 뿐 실제 공식 원천, 공급자 계약, 수집,
정규화, 역사 데이터 또는 Point-in-time 재현 조건이 완성되지 않은 항목이다.

DB 컬럼이 존재한다는 이유만으로 확보 데이터로 판정하지 않는다.

- 현재 상태:
  - 당시 보유수량, 평균단가, 현금, 계좌 설정, 목표비중의 완전한 Snapshot 부족
- 영향:
  - 시장 공통 판단은 재계산 가능
  - 과거 계좌별 매수금액과 리밸런싱은 완전 재현 불가

6.9 FULL_AVAILABLE_AT_VINTAGE

- 분류: FUTURE
- 현재 상태:
  - 입력 기준일은 저장 가능
  - 원천별 최초 공개시각과 당시 이용 가능시각은 완전하지 않음
- 목표 조건:

  AVAILABLE_DTTM <= AS_OF_DTTM

  이 조건을 충족해야 엄격한 Point-in-time 백테스트로 분류할 수 있다.

8. 버전 관리 원칙
-----------------

버전 하나로 통합하지 않는다.

권장 기준:

ALGORITHM_VERSION = MARKET_ALGORITHM_V2
RULE_VERSION      = MARKET_RULE_V1
CODE_VERSION      = Git commit hash
DATASET_VERSION   = DATASET_V1
OUTCOME_VERSION   = OUTCOME_V1

각 버전의 의미:

- ALGORITHM_VERSION
  전체 판단 체계 버전

- RULE_VERSION
  위험점수, 시장국면, 행동판단 임계값과 가중치 버전

- CODE_VERSION
  실제 실행 코드 Git commit

- DATASET_VERSION
  입력 지표 목록, 공급자, 필드 계약, 결측 정책 버전

- OUTCOME_VERSION
  평가 대상, 기간, 수익률·낙폭·변동성 계산 방식 버전


9. 알고리즘과 데이터셋 변경을 분리하는 방법
-------------------------------------------

새 지표를 기존 DATASET_V1의 SUPPLEMENT 데이터로부터 계산하는 경우:

DATASET_V1 + MARKET_ALGORITHM_V2
DATASET_V1 + MARKET_ALGORITHM_V3

예:

MARKET_ALGORITHM_V3
    └─ DELEVERAGING_RISK 추가
        ├─ VKOSPI
        ├─ CREDIT_BALANCE_TREND
        ├─ KOSPI Drawdown
        ├─ MARKET_BREADTH
        ├─ USD_KRW
        └─ DGS2 / DGS10

같은 DATASET_V1을 사용해야 알고리즘 변경의 순수 효과를 측정할 수 있다.

반대로 신규 공식 외국인 수급을 추가하는 경우:

DATASET_V2 + MARKET_ALGORITHM_V3

이 경우에는 데이터 개선 효과와 알고리즘 개선 효과를 분리해서 평가해야 한다.

각 기간의 의미:

11. 현재 가능한 검증 사이클
----------------------------

외부 API를 기다리지 않고 다음 작업을 진행할 수 있다.

1) DATASET_V1 Catalog를 DB에 등록하고 FROZEN 상태로 확정
2) 각 항목을 CORE / SUPPLEMENT / FUTURE로 등록
3) 기존 RECALC 실행에 ALGORITHM_VERSION과 DATASET_VERSION 부여
4) MARKET_RULE_V1 결과를 알고리즘 v2 기준선으로 확정
5) OUTCOME에 D+10 추가
6) LEGACY / v2 / OUTCOME 비교 지표 계산
7) v2 기준 성능 리포트 생성
8) DELEVERAGING_RISK를 SUPPLEMENT 데이터로 설계
9) 알고리즘 v3로 동일 58개 Case 재계산
10) v2와 v3의 조기경보 성능 비교

13. 주의사항
------------

1) 현재 RECALC는 AS_OF_RECONSTRUCTED다.

입력 기준일은 보존하지만 모든 공급자의 실제 당시 공개시각을 완전히
보존하지 않았으므로 엄밀한 POINT_IN_TIME이라고 부르지 않는다.

2) 외국인·기관·선물·프로그램 수급은 DATASET_V1 CORE가 아니다.

과거 재계산에서 실제 값이 없으므로 중립 기본값을 사용한 PARTIAL 결과로
관리한다.

3) 현재 포트폴리오를 과거 날짜에 적용하지 않는다.

당시 계좌 Snapshot이 없으면 시장 공통 계산만 수행하고 PORTFOLIO_MODE는
MARKET_ONLY 또는 NOT_REPRODUCIBLE로 기록한다.

4) 공급자 변경은 단순 구현 변경이 아니다.

동일 지표라도 공급자와 기준시각이 달라지면 분포가 달라질 수 있으므로
DATASET 버전 변경 여부를 검토한다.

5) 기존 조사 문서는 당시 조사 증거로 보존한다.

과거 문서의 미확보 판정을 현재 상태로 덮어쓰지 않고, 이 문서를
2026-08-31 현재 Main DB 기준 Frozen Baseline 정본으로 사용한다.


14. 최종 결론
-------------

현재 Main DB에는 DATASET_V1으로 동결하기에 충분한 2024년 이후 KRX,
Yahoo Finance, FRED, KOFIA 데이터가 있다.

외국인·기관·선물·프로그램 수급을 기다리지 않고도 다음 사이클을 진행할
수 있다.

DATASET_V1
    ↓
MARKET_ALGORITHM_V2
    ↓
58개 역사 Case RECALC
    ↓
D+1/5/10/20/60 OUTCOME
    ↓
v2 성능 기준선 확정
    ↓
DELEVERAGING_RISK를 포함한 v3 재계산
    ↓
v2와 v3의 조기경보 성능 비교

지금의 우선순위는 새로운 외부 API 탐색이 아니라 DATASET_V1 Catalog의
DB 동결, 버전 계약 적용, D+10 OUTCOME 추가, v2 기준 성능 측정이다.
